# Что осталось после редизайна

Сводка разделов «Найдено, но не исправлено» и «Запросы координатору» из отчётов 11 групп. Одинаковые запросы разных групп объединены в одну строку. ID вида TBL-3 — номера находок аудита (`claude/audit/REPORT.md`, `ROADMAP.md`).

**Шкалы** (как в ROADMAP):
- Тип изменения: patch — исправление без изменения API; minor — новое необязательное API или поведение; major — несовместимое изменение.
- Объём: S — до дня; M — несколько дней; L — неделя и больше.

**В список не входят:**
- перегенерация baseline — см. [VISUAL_CHANGES.md](./VISUAL_CHANGES.md);
- вопросы, которые уже решены гайдами:
  - BaseEmpty находится в разделе `Data` (STORIES_GUIDE §2);
  - HEX допустим в story `CustomColor` (STORIES_GUIDE §8);
  - вариант BaseTabs по умолчанию — `underline` (DESIGN_SYSTEM §4).

## Задача w16-security-tokens

Фаззинг XSS (`build/tests/fuzz`, `npm run test:fuzz`) и экспорт токенов в W3C Design Tokens (`docs/design/DESIGN_TOKENS.md`).

- **Найдено фаззингом и исправлено** (у каждой находки в тестах конкретный вход): `sanitizeHtml('<constructor>x</constructor>')` бросал `TypeError` (теги — в `Map`); результат очистки не был неподвижной точкой (`<h1><x><h2>t</h2></x></h1>`): очистка повторяется до неизменности, глубже 128 уровней отбрасывается; Markdown выводил `![](data:text/html,…)` как `<img>` (теперь только `data:image/*`); Markdown считал секунды на `[a](` × 3000 и `**a ` × 3000 и падал со стеком на `> ` × 3000 (пары скобок за один проход, предел вложенности 32); `formatRelativeTime` и BaseCommentThread падали `RangeError` на неверной дате. Исполнения скрипта и опасной ссылки в `href` фаззинг не нашёл ни на одной цели.
- **Что покрыто**: `sanitizeHtml`, `escapeHtml`, `isSafeUrl`, `resolveLinkUrl`, `normalizeLinkUrl`, `resolveLink`, `parseMarkdown`, `sanitizeSvg`, `serializeJsonLd`, BaseMarkdown, BaseAiMessage, BaseCode, BaseJsonViewer, BaseTextDiff, BaseChat, BaseCommentThread, BaseEditor (`modelValue`, вставка HTML и текста, перетаскивание, `insertHtml`, `uploadMedia`, ввод, режим кода). **Не покрыто**: BaseMediaPlayer (субтитры и названия), BaseTable с `render` в ячейках, BaseImageMap3D, BaseMap, BaseTree и BaseSelect с пользовательскими подписями, остальные компоненты — они выводят данные интерполяцией Vue и фаззингом не проверялись.
- **Ограничения среды**: прогон идёт в jsdom, не в браузере. Расхождения разбора HTML между parse5 (jsdom) и Chromium/WebKit (mXSS) так не найти; следующий шаг — тот же оракул и те же входы в Playwright Chromium (`page.evaluate`). jsdom падает сам на `style="width:calc(="` (css-tree) и на одиночном суррогате (`<p>\ude00\ude00</p>` — parse5, `RangeError: Invalid code point`); такие итерации не засчитываются и считаются в сводке как «пропущено». В самопроверках оракула (сырой опасный вход) jsdom печатает «Not implemented: Window's alert() method» из окна, на которое шпион не поставлен, — предположительно окно `iframe` (причина не выяснена); в очищенном HTML `iframe` быть не может, это проверяет список запрещённых элементов, шпион — запасная проверка. `<div>` × 5000 роняет собственный разбор jsdom: предел 128 в `sanitizeHtml` страхует приложения без браузерного парсера, но воспроизвести сам обвал в браузере нельзя.
- **Ввод в BaseEditor в тесте**: «набранный» HTML кладётся в живую область через `innerHTML` без `<iframe>`: jsdom загружает такой фрейм и вызывает его `onload` вне теста (необработанное исключение процесса). С клавиатуры `iframe` в область не попадает; значение, которое редактор отдаёт в `v-model`, проверяется на всём остальном вводе, а вставка, перетаскивание, `insertHtml` и `modelValue` идут с `<iframe>` как есть.
- **Политика адресов ресурсов** (DECISIONS): аватар, вложение, `src` у BaseImage, аудио и видео из данных приложения кит не фильтрует; фильтруются ссылки-переходы, Markdown, `sanitizeHtml` и редактор. Если владелец решит фильтровать и ресурсы — единый `isSafeImageUrl` для аватаров и вложений изменит поведение для приложений с `data:` не-картинок и нестандартными схемами.
- **Долгий фаззинг в CI**: не запускается (стоимость 20–40 минут на двух ядрах, до 2 ГБ памяти). Вариант — ночной job с `--iterations=20000` и артефактом `--report`; решение владельца.
- **Токены, экспорт тем приложения**: в `dist` попадают только четыре пресета. Тему приложения (`createTheme({ … })`) в W3C-формат выгрузить нечем: нужна публичная функция из кода экспорта (`build/tokens` сейчас — только сборка). Токены компонентов (`--rise-button-radius`…) и алиасы 1.x не входят.

- **e2e на статической сборке: 98 тестов, все проходят (4,2 мин на 2 ядрах).** `BaseEditor.e2e.spec.ts` «перетаскивание выделенного слова» падал на любой машине с другим шрифтом: двойной клик шёл по `x: 60`, и в Linux это «alpha», а не «beta»; теперь точка — центр диапазона слова. «Набор и команда отменяются…» и «нативное historyUndo…» печатали клавишами, а пауза ≥ 500 мс между клавишами (`GROUP_PAUSE` истории) под нагрузкой дробит шаг отмены: набор — `keyboard.insertText`, сочетания клавиш остались настоящими.

## Задача w16-lazy-locale

- **Языки, кроме `ru`, — словарём целиком** (английский ≈20 КБ gzip, остальные 22–25 КБ): какие разделы читают компоненты приложения, известно только сборщику приложения, а `registerLocale` принимает готовый объект. Разбить `en` по разделам можно только плагином сборки приложения (подмена импорта словаря на нужные разделы) — новый слой, без конкретной нужды осознанно не делаем.
- **Крупные общие разделы.** `text` (≈1,2 КБ gzip) и `aria` (≈2,3 КБ) читают десятки компонентов: компонент, которому нужна одна строка, получает раздел целиком. Дальше — разнести строки этих разделов по разделам компонентов; ломающее для приложений, которые переопределяют их через `defineLocale` (`text.EMPTY` → `select.EMPTY`…), — только с прежними ключами через `legacyKeys`. S–M.
- **`useLocale().messages`** отдаёт словарь целиком и поэтому тянет весь `ru` (≈26 КБ gzip). Если приложениям понадобится доступ к строкам без этого веса — `useLocale().section(name)` поверх `localized`. S.
- **Таблица `docs/reference/SIZES.md` сверяется с допуском** 3 % или 0,3 КБ: другая версия Node/zlib или Vite сжимает чуть иначе. Если обновление Vite сдвинет много строк сразу — перезаписать таблицу (`npm run build && npm run report:sizes`) отдельным коммитом.

## Задача w16-codemod

- **Кодмод разбирает код по маске, а не по AST** (в `dependencies` парсеров нет, добавлять нельзя): не разбираются шаблоны внутри строк, `lang="pug"`, JSX-шаблоны `.vue`, динамически собранные имена, переэкспорт кита через собственный barrel-файл приложения (импорт из него кодмод не считает импортом из кита) и компоненты без импорта (Nuxt auto-import, глобальная регистрация) — для плеера в шаблоне без импорта он предупреждает. Если понадобится больше точности — отдельная задача с решением владельца о парсере.
- **`.list-*`**: кодмод переименовывает в `.rise-list-*` (классы `BaseAnimation`); приложения, стилизовавшие этими классами BaseNotification, должны вручную перейти на `.base-notification-*` — отличить такие правила по коду нельзя.
- **Слот `default` у компонентов, где его убрали**, и **`events` у `BaseCalendar`** кодмод только находит: удаление содержимого из шаблона правит разметку, а на показ оно и раньше не влияло. Автоудаление — по запросу.
- **Живая проверка кодмода** (`npm run test:codemod-app`) в `ci:validate` не включена: нужна сборка `dist` и tarball, несколько минут. Включить — решение оркестратора.
- **Проверка на реальных приложениях 1.x** (например, videoPlayer владельца, только чтение) не проводилась: в окружении сессии их нет. `migrate <папка>` в режиме `--dry` ничего не меняет, запустить его на таких приложениях безопасно.
- **Код `bin/` в eslint не входит** (линтер смотрит только `src/**`): качество держат prettier, `lint:unused` (knip видит `bin` из `package.json`) и тесты со 100% покрытием.
