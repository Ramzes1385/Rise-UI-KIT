# Что осталось после редизайна

Сводка разделов «Найдено, но не исправлено» и «Запросы координатору» из отчётов 11 групп. Одинаковые запросы разных групп объединены в одну строку. ID вида TBL-3 — номера находок аудита (`claude/audit/REPORT.md`, `ROADMAP.md`).

**Шкалы** (как в ROADMAP):
- Тип изменения: patch — исправление без изменения API; minor — новое необязательное API или поведение; major — несовместимое изменение.
- Объём: S — до дня; M — несколько дней; L — неделя и больше.

**В список не входят:**
- перегенерация baseline — см. [VISUAL_CHANGES.md](./VISUAL_CHANGES.md);
- вопросы, которые уже решены гайдами:
  - BaseEmpty находится в разделе `Data` (STORIES_GUIDE §2);
  - HEX допустим в story `CustomColor` (STORIES_GUIDE §8);
  - вариант BaseTabs по умолчанию — `underline` (DESIGN_SYSTEM §4).

№ 60, замер `useScrollableRegion` в виртуальном режиме: Storybook-сборка, история `data-basetable--virtual` (5000 строк, `isVirtual`, `height`), Chromium (Playwright), 300 шагов прокрутки по кадрам, колбэк MutationObserver области пропускался и включался попеременно, по три круга. На обычной скорости процессора колбэк срабатывает 247 раз на 300 кадров (0,8 раза на кадр) и тратит 4–5 мс за весь прогон — 0,014 мс на кадр (≈0,1% кадра 16,7 мс); средний кадр с наблюдателем и без — 16,65 мс. При замедлении процессора в 6 раз (CDP `setCPUThrottlingRate`) — 0,25–0,46 мс на кадр, ≤0,7% кадра при шуме самих кадров 60–140 мс. Пересчёт на каждую перерисовку не заметен, поэтому накопление через `requestAnimationFrame` не вводилось: оно сдвигало бы `isScrollable` на кадр у всех потребителей (модальные окна, панели, код) ради выигрыша меньше шума замера. Вернуться, если появится сценарий с тысячами изменяемых узлов вне виртуального режима: там записей MutationObserver больше.
