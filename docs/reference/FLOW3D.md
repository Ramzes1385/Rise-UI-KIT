# 3D-карта потоков и 3D-роадмап: входы `/flow3d` и `/roadmap3d`

`BaseFlowMap3D` — карта взаимодействий и процессов в 3D на [three.js](https://threejs.org): узлы — модели на сетке, связи — ленты, дуги и трубы, группы — рамки и платформы, режим «Слои», сценарий с частицами, «Правка» на сцене. `BaseRoadmap3D` — учебный роадмап в виде острова: дорога, пьедесталы этапов, машинка, тур, панель этапа. Данные и поведение берутся у 2D-компонентов (`BaseFlowMap`, `BaseRoadmap`), 3D добавляет к ним сцену, камеру и модели. Без WebGL оба компонента сами показывают 2D-вид.

Компоненты живут в отдельных входах пакета: `@ramzes1385/rise-ui-kit/flow3d` и `@ramzes1385/rise-ui-kit/roadmap3d`. В корень пакета, `/components` и плагин они не входят (как `BaseImageMap3D` из `/map3d`, см. [MAP3D.md](./MAP3D.md)), поэтому приложения без 3D не загружают ни их, ни three.js. В автоимпорт Nuxt и резолвер компоненты тоже не входят.

Полный список пропсов, событий, слотов и методов — [COMPONENTS.md, «BaseFlowMap3D»](./COMPONENTS.md#baseflowmap3d) и [«BaseRoadmap3D»](./COMPONENTS.md#baseroadmap3d); типы — `src/components/BaseFlowMap3D/types/` и `src/components/BaseRoadmap3D/types/`; живые примеры — Storybook, BaseFlowMap3D и BaseRoadmap3D.

## Установка

```bash
npm i @ramzes1385/rise-ui-kit three
# типы three для TypeScript: от них зависят .d.ts входов
npm i -D @types/three
```

- `three` — **необязательная peer-зависимость** кита: `>=0.180.0 <0.200.0`. Ставит только приложение, которое импортирует `/flow3d` или `/roadmap3d`.
- Без `three` основной вход и остальные подпути собираются и работают как прежде. Импорт `/flow3d` или `/roadmap3d` без `three` (и обычный, и ленивый `import()`) не соберётся: сборщик сообщит об отсутствующем модуле или экспортах three (подробности и тексты ошибок — [MAP3D.md, «Установка»](./MAP3D.md#установка)). Это ожидаемо: установите `three`.
- Стили уже в общем `@ramzes1385/rise-ui-kit/styles`; отдельного CSS у входов нет. При точечной установке CSS компонента подключает сам вход подпути.

```vue
<script setup lang="ts">
import { ref } from 'vue'
import { BaseFlowMap3D } from '@ramzes1385/rise-ui-kit/flow3d'
import type { FlowMap3DView } from '@ramzes1385/rise-ui-kit/flow3d'
import type { FlowMapData } from '@ramzes1385/rise-ui-kit'

import '@ramzes1385/rise-ui-kit/styles'

const view = ref<FlowMap3DView>('3d')
const data: FlowMapData = {
	version: 1,
	title: 'Магазин',
	nodes: [
		{ id: 'web', kind: 'client', label: 'Сайт' },
		{ id: 'gw', kind: 'gateway', label: 'API Gateway' },
		{ id: 'orders', kind: 'service', label: 'Orders', model3d: { model: 'cart' } },
		{ id: 'db', kind: 'database', label: 'Orders DB' },
	],
	edges: [
		{ id: 'e1', kind: 'call', source: 'web', target: 'gw' },
		{ id: 'e2', kind: 'call', source: 'gw', target: 'orders' },
		{ id: 'e3', kind: 'data', source: 'orders', target: 'db' },
	],
	view3d: { camera: 'iso', isLayered: false },
}
</script>

<template>
	<BaseFlowMap3D v-model:view="view" :data="data" height="560px" @fallback="reason => console.info('Показан 2D:', reason)" />
</template>
```

Ленивая загрузка — `defineAsyncComponent(() => import('@ramzes1385/rise-ui-kit/flow3d').then(m => m.BaseFlowMap3D))`: компонент и three.js попадут в отдельный чанк и загрузятся при первом показе. Вес входов (`build/ratchets.json`, gzip вместе со статически подключаемыми общими чанками): `flow3d.js` ≈ 137 КБ (140 484 байта), `roadmap3d.js` ≈ 160 КБ (163 285 байт); для сравнения у `map3d.js` — ≈ 160 КБ. Код «Правки» в 3D, сценарий и панели 2D в эту цифру не входят: они грузятся по `import()`.

## Данные (`BaseFlowMap3D`)

Формат — тот же `FlowMapData`, что у BaseFlowMap (`version: 1`, нотации, сценарии, статусы). Любая карта 2D открывается в 3D без правок, а карту с 3D-полями открывает и BaseFlowMap — он их не читает и сохраняет. Раскладку и маршруты связей считает ядро карты (3D своей раскладки не ведёт): позиции узлов (`position` при `isPinned`) переводятся в сцену, единица плана — `view3d.unit`. 3D-поля описаны в `src/components/BaseFlowMap/types/data/flowData3d.types.ts`:

| Поле | Тип | По умолчанию | Что делает |
|---|---|---|---|
| `node.model3d.model` | строка | по порядку выбора модели (ниже) | Модель узла: id встроенной (`db`, `gateway`, `cart`…) или ключ из `models` / `createScene3DModels` |
| `node.model3d.url` | адрес | нет | Своя модель GLB/GLTF вместо `model`; только `http(s)`, `./`, `../`, `/` или `.glb` / `.gltf` |
| `node.model3d.rotation` | градусы | 0 | Поворот на сетке: 0, 90, 180, 270 (другое значение — к ближайшему, в dev — предупреждение) |
| `node.model3d.scale` | число > 0 | 1 | Масштаб модели |
| `node.model3d.elevation` | число | 0 | Подъём над землёй (ярусом), единицы сцены: мостик, «парящий» узел |
| `node.model3d.tint` | токен `var(--rise-…)` или CSS-цвет | тема и статус | Цвет корпуса |
| `edge.model3d.shape` | `ribbon` / `arc` / `tube` | `ribbon` | Лента с подписью на земле, дуга над землёй, труба |
| `edge.model3d.height` | число > 0 | 1,5 | Высота дуги, единицы сцены |
| `group.model3d.level` | число | по порядку групп верхнего уровня | Ярус в «Слоях»: 0 — земля |
| `group.model3d.base` | `dashed` / `plate` / `none` | `dashed` | Пунктирная рамка на земле, платформа, без основания |
| `step.model3d.animation` | строка или `null` | анимация модели | Какую анимацию играет узел шага сценария (у связи — приёмник); `null` — без анимации |
| `view3d.camera` | пресет камеры | `iso` | `iso`, `iso-90`, `iso-180`, `iso-270`, `top`, `perspective` |
| `view3d.isLayered` | `true` / `false` | `false` | Режим «Слои» |
| `view3d.levelGap` | число | 2,5 | Расстояние между ярусами |
| `view3d.unit` | число > 0 | 40 | Пикселей холста 2D на единицу сцены |
| `view3d.quality` | `auto` / `low` / `high` | `auto` | Качество сцены (ниже) |

**Неверное поле игнорируется** (берётся умолчание), а при разработке (`NODE_ENV !== 'production'`) в консоли — предупреждение. Так же предупреждает карта больше 300 узлов (бюджет, см. «Ограничения»). Проп компонента сильнее поля данных: `camera`, `isLayered` и `quality` без значения берутся из `data.view3d`.

## Модели

Каждый узел рисуется моделью. Встроенных моделей 35: 24 по смыслу сервисов (набор `service`: `laptop`, `phone`, `gateway`, `lock`, `cart`, `rack`, `terminal`, `bank`, `bell`, `ram`, `db`, `conveyor`, `globe`, `scales`, `search`, `analytics`, `bucket`, `mailbox`, `clock`, `scroll`, `monitor`, `ai`, `user`, `cloud`), запасные `server` и `shape` (набор `base`) и девять фигур пьедесталов роадмапа (набор `learning`: `window`, `code`, `gear`, `layers`, `flask`, `rocket`, `book`, `shield`, `flag`). Таблица с видом, анимацией и значком каждой — константа `MODEL3D_PRESETS`, список id — `MODEL3D_PRESET_IDS`. Названия моделей в палитре — раздел словаря `models3d`.

### Порядок выбора

Для узла берётся первая найденная модель:

1. `node.model3d.url` — своя GLB;
2. `node.model3d.model` — ключ;
3. проп `modelResolver(node)` — функция приложения: id встроенной или ключ из `models`, `null` и `undefined` — решает кит;
4. `model3d` вида узла в нотации (`FlowNodeKindDef.model3d`; значение `auto` пропускает шаг, вид без поля даёт `shape`);
5. слова из названия и меток узла (ru/en: `pay`, `оплат`, `база`…): свои слова сильнее встроенных при равном совпадении;
6. запасная: внешний узел — `cloud`, иначе по виду узла, иначе `server`.

Неизвестный ключ не ломает карту: в dev предупреждение «3D-модель «…» не найдена», выбор идёт дальше. Ключ ищется по порядку: проп `models` компонента → `createScene3DModels` приложения → встроенные.

### Своя модель: GLB

```ts
import { defineModel3D } from '@ramzes1385/rise-ui-kit/flow3d'

const models = {
	kiosk: defineModel3D({
		title: 'Киоск',
		words: ['kiosk', 'киоск'],
		kind: 'client',
		url: '/models/kiosk.glb',
		fit: 'footprint', // по умолчанию: вписать в клетку узла по ширине; none — как есть × scale
		paint: 'state', // по умолчанию: красить по состоянию узла; keep — материалы модели как есть
		parts: { body: 'Body', accent: 'Lamp' }, // узлы модели под роли окраски
		clips: { gate: 'BarrierOpen' }, // клипы анимаций модели под имена кита
		animation: 'gate', // анимация шага сценария по умолчанию
	}),
}
```

```vue
<BaseFlowMap3D :data="data" :models="models" />
```

- Файл отдаётся **со своего домена или с CDN с CORS**; закрытое хранилище — через свой прокси, ключи в JSON карты не кладут.
- Сжатие DRACO, KTX2 и meshopt кит не подключает: загрузчик настраивает проп `configureLoader(loader)` (пример — [MAP3D.md, «Модели GLB»](./MAP3D.md#модели-glb)).
- Каждый адрес грузится один раз на компонент, узлам отдаются клоны (со скелетами). Неудача загрузки не кешируется, следующая попытка (смена вида, новые `data`) пробует снова. Модель не загрузилась — карта переходит в 2D (`fallback('error')`).
- Другие поля GLB-определения: `scale`, `rotationY` (градусы), `offset` (`[x, y, z]`).

### Своя модель: фабрика и встроенная с настройками

```ts
import { BoxGeometry, Mesh } from 'three'
import { defineModel3D } from '@ramzes1385/rise-ui-kit/flow3d'

const models = {
	// фабрика: свой Object3D; геометрию и материалы кита освобождает кит
	pay: defineModel3D({
		title: 'Касса',
		words: ['pay', 'оплат'],
		create: (node, context) => new Mesh(context.geometry('pay-box', () => new BoxGeometry(...)), context.material('body')),
	}),
	// встроенная под своим именем: другой цвет и масштаб
	'big-db': defineModel3D({ preset: 'db', tint: 'var(--rise-warning)', scale: 1.4 }),
}
```

Фабрика получает `Model3DNode` (`id`, `title`, `kind`, `tags`, `tone`, `source`) и `Model3DContext` (`size` клетки, `color(css)`, `material(role)`, `geometry(key, build)`, `seed`, `isReducedMotion`) и возвращает `Object3D` или `Model3DInstance` (`object`, `parts` по ролям, `anchor` бирки, `animations`, `setState`, `dispose`). Роли окраски: `MODEL3D_PARTS` (`body`, `accent`, `detail`, `screen`, `metal`, `glass`, `light`); анимации — `MODEL3D_ANIMATIONS`; тон статуса — `MODEL3D_TONES`.

### Общая библиотека моделей приложения

Модели, которые нужны нескольким картам и роадмапам, регистрируются один раз плагином приложения; проп `models` компонента сильнее:

```ts
import { createScene3DModels, defineModel3D } from '@ramzes1385/rise-ui-kit/flow3d'

app.use(createScene3DModels({ kiosk: defineModel3D({ url: '/models/kiosk.glb', words: ['киоск'] }) }))
```

`createScene3DModels` кладёт определения через `provide`: у каждого приложения свои модели, общего состояния модуля нет (SSR безопасен). Это библиотека **определений**; загруженные файлы GLB кешируются отдельно, на компонент (см. «Ограничения»).

### Управление моделью из приложения

`ref.getModel(id)` / `getModels()` и хук `onModelReady` отдают `Model3DHandle`: `object` (корень, читать и добавлять своё можно, удалять нельзя), `preset`, `setState(patch)` / `clearState()`, `play(name, { duration, repeat })` / `stop()`, `setColor(color, part?)`, `setScale`, `setMaterial(part, material)`, `focus()` (наезд камеры). При «уменьшить движение» `play` сразу ставит последний кадр.

### `isMergedInstancing`

Одинаковые встроенные модели без своих настроек, цвета и материалов рисуются инстансингом: по одному `InstancedMesh` на часть (если узлов одной модели не меньше порога, по умолчанию 8). Опция реестра `isMergedInstancing` (по умолчанию выключена) дополнительно **сливает части модели с одним материалом в один `InstancedMesh`** — меньше вызовов отрисовки. `BaseFlowMap3D` включает её сам при **больше 150 узлов** (вместе с отключением мелких деталей и предела 150 частиц): 300 узлов дают 23 вызова отрисовки и ≈ 337 тыс. треугольников. Своей настройки в пропсах нет.

## Камера и «Слои»

- Пресеты `iso` (по умолчанию), `iso-90`, `iso-180`, `iso-270`, `top`, `perspective` (`camera`, `v-model:camera`, `data.view3d.camera`). `Q` и `E` — поворот на 90°, `Shift + ← →` — на 15°, `Shift + ↑ ↓` — наклон на 10°; кнопки в нижней панели повторяют эти действия и добавляют масштаб и «Сбросить вид».
- Мышь и касание: вращение — левая кнопка или один палец, сдвиг — правая кнопка или два пальца. **Колесо масштабирует только с Ctrl или ⌘** (иначе прокручивается страница); щипок на тачпаде и двумя пальцами тоже масштабирует.
- `flyTo(id)` — наезд камеры на узел и фокус клавиатуры на нём; переход 3D ↔ 2D сопровождается перелётом камеры. При «уменьшить движение» полётов нет.
- **«Слои»** (`isLayered`, `v-model:isLayered`, кнопка в панели при `hasLayersToggle`): группы верхнего уровня встают ярусами (`group.model3d.level`, `view3d.levelGap`) с плавным переходом.

## Хуки сцены

Приложение подключается к сцене тремя хуками (`Scene3DHookProps`, одинаковы у обоих компонентов):

```ts
import type { Scene3DContext } from '@ramzes1385/rise-ui-kit/flow3d'

function onSceneReady({ scene, camera, renderer, invalidate, animate, getModel }: Scene3DContext) {
	const stop = animate((delta, time) => {
		// покадровая анимация своих объектов; вернуть false — остановить
	})
	invalidate() // перерисовать кадр (кадры рисуются по требованию)
	return () => stop() // вызовется перед пересборкой сцены и при размонтировании
}
```

- `onSceneReady(context)` — сцена собрана (и после пересборки по новым `data`); возвращённая функция вызывается перед пересборкой и размонтированием.
- `onBeforeRender(context, { delta, time })` — перед каждым кадром (только если задан).
- `onModelReady(handle)` — модель узла создана (GLB — после загрузки).
- `rendererFactory(canvas)` — свой рендерер (особые настройки WebGL, тесты); ошибка внутри — 2D и `fallback('error')`. Интерфейс — `Scene3DRenderer`.

## Клавиатура и скринридер

Область сцены — **одна точка Tab** (`role="group"`, подсказка по `aria-describedby`), узлы по отдельности не фокусируются. Клавиши в области `BaseFlowMap3D`:

| Клавиша | Действие |
|---|---|
| ← → ↑ ↓ | к ближайшему узлу в эту сторону экрана (видимые на экране) |
| `]` и `[` | по связям вперёд и назад |
| Home / End | первый / последний узел |
| Enter / Пробел | выбрать узел |
| Escape | снять выбор |
| Q / E | поворот камеры на 90° |
| Shift + ← → / Shift + ↑ ↓ | поворот на 15° / наклон на 10° |
| `+` / `=` и `-` | масштаб |
| `0` | исходный вид |
| буквы | поиск узла по названию |

**Поиск по буквам.** Набор букв переходит к узлу, название которого начинается с набранного (набор сбрасывается через 700 мс паузы). Буква продолжает набор, если с предыдущей буквы прошло меньше 700 мс или она набрана с Shift. Вне набора без Shift буквы `Q` и `E` (четверть оборота камеры) и, в «Правке» при выбранном узле, `R` и `C` остаются командами; названия, начинающиеся с Q, E, R или C, начинаются с Shift+буква. Любая неалфавитная клавиша (кроме модификаторов) сбрасывает набор.

Без мыши узел выбирается стрелками, скрытым списком узлов по группам (есть и в разметке сервера) или 2D-видом (`has2dToggle`: BaseFlowMap, где узлы — элементы в порядке Tab). Озвучиваются смена вида, «Слои», частицы, фокус и состояния загрузки и ошибки (текст попадает в живую область после монтирования и при смене). Корень компонента несёт `role="region"` и название только в 3D; в 2D-виде эту роль несёт вложенная карта. Цвета ролей сцены в тёмной теме поднимаются до контраста с землёй не ниже 3,2; токены `--rise-scene3d-*` имеют приоритет.

## «Правка» в 3D

Кнопка «Правка» в нижней панели (если в `modes` есть `edit`) и `mode: 'edit'` включают правку на сцене. На контейнере уже 768 px кнопки нет, а `mode: 'edit'` показывает правку ядра карты в 2D.

- **Что умеет**: перенос узла по земле с привязкой к сетке (призрак и целевая клетка; занятая клетка отклоняется; Escape отменяет), поворот на 90° (`R`), замена модели (палитра: «Схема» — модели, уже стоящие на карте, «Ещё в реестре» — остальные встроенные и ключи `models`, свой GLB по адресу), инструмент «Связь» (`C`: протянуть линию; проверка `canConnect` нотации, текст отказа), удаление, панель действий выбранного узла, инспектор свойств с разделом «3D» (через слот `inspector-end` 2D-инспектора).
- **Клавиатура**: стрелки двигают выбранный узел на шаг сетки (подряд идущие шаги склеиваются в одну запись истории), Alt + стрелки — навигация по узлам, Shift + стрелки — камера, Enter — свойства (в режиме связи — создать связь), Delete / Backspace — удалить, Escape, `Ctrl/⌘+Z`, `Ctrl/⌘+Y`, `Ctrl/⌘+Shift+Z`.
- **Все действия идут через публичный контроллер** (`move`, `updateNode`, `connect`, `remove`, `transact`, `undo`, `redo`): хук `beforeDelete`, `beforeConnect`, правила нотации и события (`change`, `reject`, `update:data`) работают как в 2D.
- **Общая история с 2D.** `BaseFlowMap3D` отдаёт свою модель встроенному 2D-виду, поэтому правка в 3D отменяется в 2D и наоборот (удаление в 2D отменяется в 3D, добавление в 3D — в 2D). Режим следует за видом карты, а не за пропом. Передача внешней модели в BaseFlowMap — внутренний механизм (`provide`), публичного API у него нет.
- **Загрузка по `import()`**: палитра моделей, инспектор, панель действий, перенос и связь собираются при входе в `mode: 'edit'` одним шагом; до загрузки правка неактивна.
- «Правки» (`review`) в 3D нет: режим показывает 2D-вид BaseFlowMap.

## Запасной 2D-вид

- **Автоматически 2D**: нет WebGL (`fallback('unsupported')`), рендерер не создался, контекст потерян и не вернулся за 3 с или модель не загрузилась (`fallback('error')`). Под картой плашка с причиной (`role="status"`). Если 2D выбрало приложение (`view="2d"`), события и плашки нет.
- 2D-вид получает данные, выбор, сценарий, слоты, `isAutoplay`, `choices`, `live`, хуки и события и возвращает их изменения; состояние (выбор, сценарий, история) при переключении вида сохраняется.
- **SSR**: на сервере (без `window` и `document`) рисуется 2D-вид и скрытый список узлов, без холста; WebGL проверяется и холст создаётся в `onMounted`, гидратация идёт без расхождений. `three` на сервере не вызывается.
- `exportSvg` работает только через 2D-вид (иначе событие `error`); `exportPng` отдаёт кадр холста без бирок.

## Ограничения и бюджеты

- **Бюджет сцены**: до 300 узлов, не больше 60 вызовов отрисовки, не больше 350 тыс. треугольников. Предел 300 узлов — предупреждение в dev, а не отказ: сверх него карта строится, но может не уложиться по кадрам.
- **Качество** (`quality`): `auto` — тени картой (`ShadowMaterial`) при не более 80 узлов, иначе пятна-тени; `low` — без теней и мелких деталей; `high` — тени всегда. Мелкие детали моделей скрываются, если клетка узла на экране меньше 18 px. Плотность пикселей — `min(devicePixelRatio, 2)`.
- **Кадры по требованию**: в покое (пауза, частицы выключены) кадры не рисуются; рисование ставится на паузу при скрытой вкладке и вне экрана (при наличии `IntersectionObserver`). При «Уменьшить движение» ничего не движется: частицы стоят, полётов камеры нет.
- Частицы — по `particles` (предел 400; при больше 150 узлах — 150); токен сценария — по состоянию сценария модели карты (только публичный API).
- **Файлы GLB кешируются на компонент**, а не на страницу: две 3D-сцены на странице, использующие один адрес, скачивают файл каждая (повторный запрос обслуживает HTTP-кеш браузера).
- Вне 3D: `panels`, `suggestions`, `comments`, `versions`, `compareWith`, `currentUser`, `savedAt` (они нужны только 2D-виду «Правок»); у 3D свои панели — нижняя панель, бирки, палитра и инспектор «Правки».
- Картинка WebGL зависит от GPU и драйвера, поэтому скриншот-тестов 3D-видов в ките нет; снимается только 2D-вид.
- Жизненный цикл: сцена — обычные объекты three.js вне реактивности Vue; размонтирование и замена данных освобождают геометрии, материалы, текстуры и рендерер (`dispose`, `forceContextLoss`); ответы загрузки, пришедшие после замены `data` или размонтирования, отбрасываются.

## BaseRoadmap3D

Остров-роадмап: змейка дороги с пьедесталами этапов, финишная площадка цели, горы, деревья и облака (по `quality`), машинка на текущем этапе. Данные — `RoadmapData` (тот же JSON, что у BaseRoadmap), прогресс — `progress` / `storage`, режимы, хуки и события роадмапа работают так же.

```vue
<script setup lang="ts">
import { ref } from 'vue'
import { BaseRoadmap3D } from '@ramzes1385/rise-ui-kit/roadmap3d'
import type { Roadmap3DView } from '@ramzes1385/rise-ui-kit/roadmap3d'
import type { RoadmapData, RoadmapProgress } from '@ramzes1385/rise-ui-kit'

const view = ref<Roadmap3DView>('3d')
const focused = ref<string | null>(null)
const progress = ref<RoadmapProgress>({ version: 1, topics: {} })
const data: RoadmapData = {
	version: 1,
	title: 'Старт во Vue',
	goal: 'Frontend-разработчик',
	stages: [
		{ id: 'basics', title: 'Основы', model3d: { model: 'code', tint: 'var(--rise-chart-1)' }, topics: [{ id: 'template', title: 'Шаблоны', hours: 4 }] },
		{ id: 'router', title: 'Маршрутизация', topics: [{ id: 'routes', title: 'Маршруты', hours: 3 }] },
	],
	view3d: { perRow: 2, hasCar: true },
}
</script>

<template>
	<BaseRoadmap3D v-model:view="view" v-model:focused="focused" v-model:progress="progress" :data="data" />
</template>
```

- **3D-поля данных**: у этапа `model3d` (`model` — id встроенной модели или ключ из `models`, `url` — свой GLB, `scale`, `tint`; цвет по умолчанию — `--rise-chart-<n>` по номеру этапа), у пути `view3d` (`seed` — зерно гор, деревьев, облаков и берега, по умолчанию хеш `id ?? title`; `perRow` — этапов в ряду змейки, 2–4; `hasCar` — машинка; `camera` — пресет камеры). Модели пьедесталов — те же реестр, `models`, `createScene3DModels` и порядок выбора (без шагов вида нотации), что у карты; по умолчанию модель выбирается по ключевым словам названия этапа.
- **Фокус на этапе**: `focused` (`v-model:focused`) и метод `focusStage(id)` — камера наезжает на этап, открывается панель этапа с темами, статусами и материалами (слоты `topic-details` и `material` передаются и ей); `null` — весь остров.
- **Тур**: кнопка «Тур по этапам» (`hasTour`, по умолчанию `true`), `isTourPlaying` (`v-model:isTourPlaying`), `setTour(isPlaying)`. Фокус переходит на следующий этап каждые 2,6 с; любой ввод (клавиша, касание) тур останавливает.
- **Телефон и узкий контейнер**: контейнер уже `compactBreakpoint` (640 px) — остров рисуется без мелочи (деревья, облака, блёстки), панель этапа — шторкой, этапы листаются кнопками «Назад / Далее» вместо полосы этапов.
- **Правка через панель**: режим `edit` открывает в панели этапа форму — название, порядок («Раньше» / «Позже»), модель пьедестала и адрес своего GLB, «Добавить этап», «Удалить». Все изменения идут командами роадмапа (`beforeChange`, `beforeDelete`, `update:data`, `reorder`), история общая с 2D. С клавиатуры: `Alt + ← →` на этапе в фокусе переставляет его. Режим `review` («Правки») показывает 2D-вид BaseRoadmap.
- **Клавиатура** (область острова — одна точка Tab): ← ↑ / → ↓ — предыдущий / следующий этап, Home / End — первый / последний, Enter и Пробел — открыть этап (текущий или первый), Escape — закрыть тему, затем вернуться к острову; Q / E, `Shift + стрелки`, `+`, `-`, `0` — камера, как у карты. Скрытый список этапов есть и в разметке сервера.
- **Запасной 2D-вид**: без WebGL, при ошибке рендерера, потере контекста или неудачной загрузке модели показывается `BaseRoadmap` (`layout="path"`) с теми же данными, прогрессом, выбором и событиями; `fallback` называет причину. Качество: `auto` — тени картой и весь декор, на узком контейнере без мелочи; `low` — без теней, деревьев, облаков и блёсток; `high` — всё.
- Хуки сцены, `rendererFactory`, `configureLoader`, ограничения и бюджеты — как у карты (разделы выше).
