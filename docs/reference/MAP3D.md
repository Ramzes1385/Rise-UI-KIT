# 3D-карта этажей: вход `/map3d`

`BaseImageMap3D` — карта торгового центра, офиса или кампуса в 3D на [three.js](https://threejs.org): этажи стопкой, объекты выдавлены из плана или взяты из модели GLB, камера с вращением, выбор, каталог и маршруты. Данные — тот же JSON, что у 2D-карты `BaseImageMap` (его рисует BaseImageMapEditor), плюс несколько необязательных 3D-полей. Без WebGL карта сама показывает 2D-план.

Компонент живёт в отдельном входе пакета `@ramzes1385/rise-ui-kit/map3d`: в корень пакета, `/components` и плагин он не входит, поэтому приложения без 3D-карты не загружают ни его, ни three.js.

Полный список пропсов, событий, слотов и методов — [COMPONENTS.md, «BaseImageMap3D»](./COMPONENTS.md#baseimagemap3d); живые примеры — Storybook, раздел Media/BaseImageMap3D.

## Установка

```bash
npm i @ramzes1385/rise-ui-kit three
# типы three для TypeScript: от них зависят .d.ts входа /map3d
npm i -D @types/three
```

- `three` — **необязательная peer-зависимость** кита: `>=0.180.0 <0.200.0` (кит проверен на 0.186). Ставит только приложение, которое импортирует `/map3d`.
- Без `three` основной вход (`@ramzes1385/rise-ui-kit`, `/components` и остальные) собирается и работает как прежде — проверено сборкой Vite 8 и `vue-tsc` в чистом приложении без `three`. Импорт `/map3d` без `three` (и обычный, и ленивый `import()`) падает **при сборке**, а не в браузере: Vite 8 подменяет отсутствующую необязательную peer-зависимость пустым модулем и пишет `[MISSING_EXPORT] "AmbientLight" is not exported by "__vite-optional-peer-dep:three:@ramzes1385/rise-ui-kit"` (по строке на каждый класс three); другие сборщики — `Could not resolve "three"`. Это ожидаемо: установите `three`. TypeScript без `@types/three` на типах `/map3d` пишет `Cannot find module 'three'`.
- Стили карты уже в общем `@ramzes1385/rise-ui-kit/styles` (`styles.css` или `styles.layer.css`); отдельного CSS у входа нет.

```vue
<script setup lang="ts">
import { ref } from 'vue'
import { BaseImageMap3D } from '@ramzes1385/rise-ui-kit/map3d'
import type { ImageMap3DData, ImageMap3DView } from '@ramzes1385/rise-ui-kit/map3d'

import '@ramzes1385/rise-ui-kit/styles'

const view = ref<ImageMap3DView>('3d')
const active = ref<string | null>(null)

const data: ImageMap3DData = {
	version: 1,
	layers: [
		{ id: 'f1', title: 'Этаж 1', shortTitle: '1', image: '/maps/floor-1.svg', width: 1000, height: 600, elevation: 0 },
		{ id: 'f2', title: 'Этаж 2', shortTitle: '2', image: '/maps/floor-2.svg', width: 1000, height: 600 },
	],
	objects: [
		{ id: 'shop-101', title: 'Магазин 101', layer: 'f1', type: 'rect', x: 0.1, y: 0.2, width: 0.2, height: 0.25, height3d: 40 },
		{ id: 'cafe', title: 'Кофейня', layer: 'f2', type: 'rect', x: 0.6, y: 0.5, width: 0.15, height: 0.2 },
	],
	scene3d: { floorGap: 220 },
}
</script>

<template>
	<BaseImageMap3D
		v-model:view="view"
		v-model:active="active"
		:data="data"
		has-directory
		has2d-toggle
		height="560px"
		@fallback="reason => console.info('Показан план:', reason)" />
</template>
```

Вход не нужно регистрировать в плагине: импортируйте компонент там, где он нужен (как `BaseMediaPlayer` из `/media`). Ленивая загрузка — `defineAsyncComponent(() => import('@ramzes1385/rise-ui-kit/map3d').then(m => m.BaseImageMap3D))`: карта и three.js попадут в отдельный чанк и загрузятся при первом показе (в чистом приложении на Vite 8 — ≈270 КБ gzip вместе с three и общими частями кита, основной чанк — ≈31 КБ).

## Формат данных

`ImageMap3DData` = `ImageMapData` (формат BaseImageMap и BaseImageMapEditor, `version: 1`) с необязательными полями ниже. Любой JSON 2D-карты подходит без правок, а JSON с 3D-полями открывает и BaseImageMap — он их не читает.

Единицы — **единицы слоя**: `width` × `height` слоя (пиксели картинки или единицы viewBox SVG). Объекты 2D заданы долями (`x: 0.1` — 10 % ширины), в 3D они переводятся в единицы слоя.

| Поле | Тип | По умолчанию | Что делает |
|---|---|---|---|
| `layer.elevation` | число | номер этажа × `scene3d.floorGap` | Высота этажа по вертикали. Этажи идут снизу вверх в порядке `layers` |
| `layer.model` | `{ url, scale?, position?, rotationY? }` | нет | Этаж из модели GLB/GLTF вместо пола с картинкой. `url` — адрес модели; `scale` — масштаб (больше 0, по умолчанию 1); `position` — сдвиг `[x, y, z]` в единицах слоя; `rotationY` — поворот вокруг вертикали в градусах |
| `object.height3d` | число ≥ 0 | `scene3d.objectHeight` | Высота выдавливания объекта (`rect`, `ellipse`, `polygon`, `svg`). Не `height`: у `rect` это размер в плане |
| `object.meshName` | непустая строка | `id` объекта | Имя узла объекта в модели этажа |
| `object.parts` | `[{ elementId, height3d?, base3d? }]` | нет | Составной объект `svg`: тело — объединение частей. Часть — элемент SVG слоя (`elementId` со всеми вложенными фигурами), `height3d` — её высота (по умолчанию высота объекта), `base3d` — основание: подъём над полом этажа, 0 по умолчанию (козырёк, мостик, перекрытие). Выбор, наведение, фильтры и цвет общие у объекта. Пустой список — как без `parts`; у других видов объектов не учитывается |
| `scene3d.floorGap` | число ≥ 0 | 0,25 × большая сторона слоя | Расстояние между этажами без своего `elevation` |
| `scene3d.floorThickness` | число > 0 | 4 | Толщина плиты этажа |
| `scene3d.objectHeight` | число ≥ 0 | 0,03 × большая сторона слоя | Высота объектов без `height3d` |
| `scene3d.bevel` | число ≥ 0 | 0,002 × большая сторона слоя | Скос кромок тел в единицах слоя, 0 — без скоса. Не больше четверти высоты тела; по ширине — не больше половины «полуширины» фигуры (площадь без дыр, делённая на периметр) и четверти ширины её самого узкого места (перемычка, коридор). Считается для каждой фигуры отдельно: мелкая фигура не выключает скос у крупной. Кривые SVG делятся на 10 отрезков, кривые `ellipse` — на 24 |
| `scene3d.outline` | `true` / `false` | `true` | Тонкий контур по рёбрам тел — там, где поверхность поворачивает больше чем на 30° (кромки скоса, углы стен); на плавных кривых контура нет. Цвет — цвет тела × 0,55; в выбор лучом не участвует. У этажей из GLB контуров нет |

- **Неверное поле игнорируется** (берётся умолчание), а при разработке (`NODE_ENV !== 'production'`) в консоли — предупреждение: `[rise-ui-kit] BaseImageMap3D: layers["f1"].model.scale = 0 не учтено — ожидается число больше 0`. Те же правила проверяют поля 3D редактора BaseImageMapEditor (`has3dFields`) при вводе: неверное значение — ошибка под полем, JSON не меняется. `importJson` и `v-model` редактора 3D-поля не проверяют — неверные карта проигнорирует с тем же предупреждением.
- **Этаж без модели**: плита толщиной `floorThickness` с картинкой слоя сверху (`image`, `svg` или `svgUrl`; SVG очищается тем же белым списком, что у 2D), объекты — выдавленные тела цвета своего стиля и группы. Точки (`point`) — метки HTML над сценой.
- **Этаж из модели**: координаты модели — в единицах плана: X = `x` × `width`, Z = `y` × `height` (левый верхний угол плана — начало), Y — вверх. Узел объекта ищется по `meshName ?? id`; загрузчик GLTF заменяет пробелы в именах на `_` — кит ищет и так. Все меши узла окрашиваются по состоянию объекта; меш, уже отданный одному объекту, другому не переназначается (общий `meshName` или вложенные узлы — второй объект берёт только свободные меши, в dev — предупреждение). Узла нет — объект выдавливается по своей фигуре, в dev — предупреждение.

## План в SVG: координаты, поддерживаемые элементы, составные объекты

Объект `type: 'svg'` берёт фигуру из SVG слоя (`svg`, `svgUrl` или SVG в `image`) по `elementId`: 3D выдавливает тот же контур, который рисует 2D-карта.

**Единицы и оси сцены.** Единица сцены — единица слоя (`width` × `height`). Начало — левый верхний угол плана: X вправо (`x` × `width`), Z вниз (`y` × `height`), Y вверх; этаж стоит на высоте `elevation`. Тела, метки `point`, маршруты, модели GLB и камера пользуются одним соответствием, поэтому подложка, тела и метки совпадают на любом этаже.

**Из SVG в единицы слоя.** Правила общие у 2D и 3D (`BaseImageMap/model/svg/svgViewport`), так подложку рисует и браузер:

1. есть `viewBox` — он задаёт систему координат SVG (ненулевое начало учитывается);
2. нет — берутся `width` и `height` корня (`px`, `in`, `cm`, `mm`, `pt`, `pc`; проценты не считаются);
3. нет и их — размер слоя.

`preserveAspectRatio` учитывается целиком (`meet`, `slice`, `none`, девять выравниваний). Если пропорции `viewBox` и слоя разные, тела сдвигаются и масштабируются так же, как картинка пола. Вложенные `transform` предков элемента (`translate`, `scale`, `rotate`, `skewX`, `skewY`, `matrix`) применяются.

**Что строится.** SVG слоя проходит тот же белый список тегов и атрибутов, что у 2D (`sanitizeSvg`): без скриптов, `foreignObject`, внешних ссылок и блоков `<style>`.

| Элемент SVG | В 3D |
|---|---|
| `path` (прямые, кривые Безье, дуги, несколько контуров), `rect` (в том числе `rx` / `ry`), `circle`, `ellipse`, `polygon`, `polyline` | выдавливается; вложенный контур — отверстие: при `fill-rule: nonzero` — обратного направления, при `evenodd` — любого |
| `g` или другой элемент с `id` = `elementId` | выдавливаются все фигуры внутри |
| `use` (`href`, `x` / `y`, `transform`; на фигуру, группу или `symbol`) | раскрывается в копию без `id`: до 6 уровней вложенности, 500 раскрытий и 20 000 скопированных элементов; сверх предела оставшиеся `use` не строятся, в dev — предупреждение. Ссылки по кругу, битые и внешние пропускаются |
| `display: none`, `visibility: hidden` или `collapse` (атрибутом или в `style`) | элемент не строится; `display: none` скрывает всё внутри, `visibility: hidden` — кроме потомков с `visibility: visible` (как в браузере) |
| `defs`, `clipPath`, `mask`, `pattern`, `symbol` (сами по себе), `text`, `image`, градиенты, `line` | не выдавливаются: это не фигуры или у них нет площади |
| вложенный `<svg>` (его `x`, `y`, размеры и `viewBox` не применяются), проценты в размерах (читаются как обычные числа: `50%` — это 50), `clip-path` и `mask` как эффект, скрытие через класс или `<style>` (правила `display: none` и `visibility` из `<style>` не читаются — элемент строится), `fill: none` | **не поддерживаются**: фигура строится по своему контуру без этого эффекта (обрезка не применяется, `fill` не учитывается — тело строится и у элемента без заливки) |

Элемент объекта или части внутри элемента другого объекта или части (например, `elementId` магазина внутри `elementId` всего этажа) выдавливается дважды — у каждого; в dev — предупреждение `элемент «…» лежит внутри «…»`.

Элемент без фигуры (нет в SVG, скрыт, без площади, не поддерживается) не ломает карту: объект остаётся в каталоге, списке и 2D-виде, в 3D не показан, а в dev в консоли — `BaseImageMap3D: в SVG этажа «f2» нет фигуры для элемента «…» (элемента нет, он скрыт, без площади или не поддерживается) — объект «…» в 3D не показан`.

**Составные объекты (`parts`).** Здание из нескольких элементов с разной высотой и подъёмом — один объект: выбор, наведение, фильтры, цвет и карточка общие, меш у каждой части свой.

```json
{
	"id": "pavilion",
	"type": "svg",
	"title": "Павильон",
	"layer": "f1",
	"elementId": "pavilion-walls",
	"height3d": 30,
	"parts": [
		{ "elementId": "pavilion-walls", "height3d": 30 },
		{ "elementId": "pavilion-canopy", "height3d": 4, "base3d": 26 },
		{ "elementId": "pavilion-bridge", "height3d": 3, "base3d": 20 }
	]
}
```

Часть без фигуры пропускается с предупреждением в dev (`…нет фигуры для части «…» объекта «…»`), остальные остаются; если фигур нет ни у одной, объект в 3D не показан. Верх стартового кадра камеры — верх самой высокой части.

**Тела.** Кромки скошены (`scene3d.bevel`), по рёбрам идёт тонкий контур (`scene3d.outline`): силуэты читаются на светлой плите без постобработки. Контур наследует состояние объекта (наведение и выбор делают его ярче). Тела и контуры на прозрачных этажах (неактивных в `layerMode: 'stack'`) не пишут глубину — иначе они «просвечивали» бы призраками друг сквозь друга. Тело — выдавленная заливка контура; кривые разбиваются на 24 отрезка. Тела нулевой высоты дают тонкую плиту (0,5), а не пустоту.

В Storybook **Media/BaseImageMap3D → Detailed3D** — демо с условной геометрией (круглый угол, двор-отверстие, павильон из трёх частей, колоннада под изогнутой кровлей, тонкая стена, овальный корпус). Это демо-данные из `stories/demo/detailedPlan.ts`, а не данные какого-либо здания: фактических деталей объектов кит не выдумывает, формы и высоты в своих картах задаёт приложение.

## Модели GLB

- Модель этажа приложение отдаёт **со своего домена или с CDN с CORS** (`Access-Control-Allow-Origin`): кит грузит `layer.model.url` через `GLTFLoader` (fetch). Закрытое хранилище — через свой посредник (прокси) с проверкой доступа; ключи хранилища в JSON карты не кладите.
- Одна модель — один этаж. Масштаб, сдвиг и поворот подгоняются `layer.model.scale`, `position`, `rotationY`, а не правкой модели.
- **Сжатие DRACO, KTX2, meshopt** кит не подключает (декодеры весят сотни КБ и лежат у приложения). Подключите их пропом `configureLoader` — он получает `GLTFLoader` перед загрузкой:

```ts
import { DRACOLoader } from 'three/addons/loaders/DRACOLoader.js'
import { KTX2Loader } from 'three/addons/loaders/KTX2Loader.js'
import { MeshoptDecoder } from 'three/addons/libs/meshopt_decoder.module.js'
import type { GLTFLoader } from 'three/addons/loaders/GLTFLoader.js'

const draco = new DRACOLoader().setDecoderPath('/draco/') // файлы декодера — из node_modules/three/examples/jsm/libs/draco/

function configureLoader(loader: GLTFLoader) {
	loader.setDRACOLoader(draco)
	loader.setMeshoptDecoder(MeshoptDecoder)
	// KTX2 нужен рендерер: new KTX2Loader().setTranscoderPath('/basis/') и detectSupport(renderer) в своей rendererFactory
}
```

```vue
<BaseImageMap3D :data="data" :configure-loader="configureLoader" />
```

- Модель не загрузилась (404, CORS, битый файл) — карта показывает 2D-план, сообщение «Не удалось запустить 3D — показан план» (`role="status"`), событие `fallback('error')` и в dev — предупреждение с адресом и ошибкой. Следующий переход в 3D (`setView('3d')`, `v-model:view`, переключатель «3D / 2D») или новые `data` пробуют снова.

## Камера и этажи

- Легенда групп (`hasLegend`), кнопка «Во весь экран» (`hasFullscreen`, по умолчанию `true`) и пульсация меток (`isPulsing` и поле `isPulsing` точки) работают так же, как у BaseImageMap: легенда — тот же список «Легенда» под областью карты; полноэкранный режим — Fullscreen API, а где его нет (iPhone) — запасной слой поверх страницы с блокировкой прокрутки, Escape и возврат фокуса на кнопку; пульсация — кольцо вокруг метки по `transform` и `opacity` на токенах движения (при «уменьшить движение» без неё).

- `camera`: `isometric` (по умолчанию) — ортографическая изометрия, вид сверху под 35° с поворотом 45°; `perspective` — перспектива.
- `layerMode`: `stack` (по умолчанию) — все этажи стопкой, неактивные полупрозрачны (0,25); `single` — виден только активный этаж.
- Этаж выбирается переключателем «Этажи» над картой (если этажей больше одного), `v-model:layer`, `setLayer(id)`, клавишами PageUp/PageDown; камера переезжает на высоту этажа. Событие `layer-change(id)`.
- Мышь и касание: вращение и наклон — левая кнопка или один палец (`hasOrbit`, по умолчанию `true`), сдвиг — правая кнопка или два пальца. Наклон 5–75° от вертикали, масштаб 0,5–8×. **Колесо масштабирует только с Ctrl или ⌘** — без них прокручивается страница; щипок на тачпаде работает. Щипок двумя пальцами на сенсорном экране — тоже масштаб. Касание: при `hasOrbit: true` холст забирает жесты себе (`touch-action: none`), при `hasOrbit: false` один палец прокручивает страницу (`touch-action: pan-x pan-y`), масштаб — кнопками.
- Кнопки камеры (`hasZoomControls`, по умолчанию `true`; выключить — `:has-zoom-controls="false"`, тогда с одним этажом панели над картой нет): «Увеличить», «Уменьшить», «Повернуть влево», «Повернуть вправо», «Сбросить вид». Методы через `ref`: `zoomIn()`, `zoomOut()`, `rotate(degrees)`, `resetCamera()`, `zoomToObject(id)` (этаж объекта и камера на нём).
- Переходы камеры и рост линии маршрута — по токену `--rise-duration-xslow` (500 мс в пресете движения `standard`); при `prefers-reduced-motion: reduce`, пресете `none` (`data-rise-motion` на `<html>` или на обёртке карты) и `reducedMotion: 'always'` — сразу конечное состояние.
- Цвета сцены — из токенов `--rise-*` и стилей карты (`styles`, группы); пересчитываются при смене `data-theme`, `data-rise-theme` и системной темы.
- **Стартовый кадр** вписывает всю стопку этажей (в `single` — один этаж) и не зависит от пропорций области: изометрия берёт размер кадра по цилиндру вокруг границ сцены, у перспективы расстояние и угол обзора подбираются по ободу цилиндра: угол обзора — не больше 60° (без «рыбьего глаза» на телефоне в портрете), остальное добирается расстоянием камеры. Верхний этаж не обрезается ни в узкой, ни в широкой области, ни в башне из высоких частей. Модели этажей (GLB) после загрузки расширяют кадр по своим границам: высокая модель тоже видна целиком; если камеру ещё не двигали, она переходит в новый стартовый кадр.
- Цель камеры в `stack` — центр стопки; за активным этажом камера следует при смене этажа и при приближении больше 1,05× (в `single` цель — высота активного этажа). Сдвиг цели ограничен границами сцены с запасом 10 % радиуса: карту нельзя потерять за краем экрана. Ближняя и дальняя плоскости считаются по расстоянию до цели и размеру сцены.
- **Потеря контекста WebGL** (драйвер, нехватка памяти): кит отменяет событие, ждёт восстановления 3 с и перерисовывает сцену; не вернулся — показывается 2D-план и приходит `fallback('error')`.

## Выбор, клавиатура и скринридер

- Щелчок или касание по объекту активного этажа выбирает его (`select`, `update:active`) и выполняет действие объекта — `popup`, `link`, `layer` или `defaultAction`, как у BaseImageMap. Щелчок или касание со сдвигом больше 4 px (перетаскивание камеры, прокрутка) не выбирает. Наведение — `hover(object | null)` и карточка у объекта (`hasTooltip`, слот `tooltip`); объект под указателем ищется не чаще раза в кадр.
- Область карты — **одна точка Tab**; имя области — `ariaLabel` и текущий этаж («ТЦ «Галерея», Этаж 2»), без `ariaLabel` — название этажа. Уход фокуса из карты снимает фокус объекта и карточку; переход к кнопкам, каталогу и окну объекта — нет. Стрелки, Home и End ведут только по объектам, которые видны на экране. Клавиши в области:

| Клавиша | Действие |
|---|---|
| ← → ↑ ↓ | к соседнему объекту в эту сторону экрана |
| Home / End | первый / последний объект этажа |
| Enter / Space | открыть объект (его действие) |
| Escape | снять фокус объекта |
| PageUp / PageDown | этаж выше / ниже |
| Shift + ← / → | поворот камеры на 15° |
| Shift + ↑ / ↓ | наклон камеры на 10° |
| `+` / `=` и `-` | масштаб |
| `0` | исходный вид |

- Объект в фокусе и смену этажа объявляет `aria-live="polite"` («Магазин 101, Этаж 1», «Показан этаж: Этаж 2»); подсказка по клавишам — `aria-describedby`.
- Объекты сцены и метки не фокусируются по отдельности (Tab). Выбрать объект без мыши можно четырьмя путями: стрелки в области карты, **скрытый список объектов** (ниже), **каталог** (`hasDirectory`: список с поиском и фильтрами, обычные кнопки) и **2D-вид** (`has2dToggle` или `v-model:view="'2d'"`: BaseImageMap, где каждый объект — элемент в порядке Tab).
- **Список объектов для скринридера.** Без каталога рядом с областью лежат скрытые визуально списки кнопок объектов **всех этажей** — по списку на этаж (`ul` «Список объектов, Этаж 1», «…, Этаж 2»), список текущего этажа первым; они есть и в разметке сервера. Кнопка объекта другого этажа переключает этаж и выбирает объект (как строка каталога), а `aria-live` объявляет «Показан этаж: …»; фокус на такой кнопке сцену не подсвечивает. Состав — те же объекты, что видны в сцене: фильтры и «открыто сейчас» учитываются, поиск сужает только каталог (как в 2D). Кнопка устроена как строка каталога: `aria-current` у выбранного, `aria-disabled` у отключённого, `aria-haspopup="dialog"` у объектов с окном, ссылка `<a>` у объектов-ссылок (внешняя — в новой вкладке). Нажатие идёт тем же путём, что щелчок по объекту: `select`, `update:active`, окно или действие объекта; отключённый объект ничего не делает. В порядок Tab кнопки не входят (`tabindex="-1"`): для клавиатуры есть стрелки в области; скринридер ходит по списку своими командами, а фокус на кнопке подсвечивает объект в сцене. С `hasDirectory` списка нет — каталог даёт то же.

## Маршруты

`hasRoutes`, `v-model:route`, событие `route-change(result | null)`, методы `showRoute(from, to)` и `clearRoute()`, панель «Как пройти» — те же, что у BaseImageMap, и тот же граф `data.routes`. В 3D путь — трубка цвета `--rise-primary` поверх этажей с вертикальными участками на лестницах и лифтах; линия вырастает от начала к концу. В `layerMode: 'single'` рисуется только участок текущего этажа, как в 2D: переход на другой этаж отмечен жёлтой меткой (`--rise-warning`), при смене этажа линия перестраивается; на этаже без участка маршрута сцена без линии.

## 2D-вид и фолбэк

- `v-model:view`: `3d` (по умолчанию) или `2d` — BaseImageMap с теми же данными, пропсами и слотами. Переключатель «3D / 2D» над картой — `has2dToggle` (по умолчанию выключен). 2D-вид получает выбранный объект, этаж, поиск, фильтры и маршрут и возвращает их изменения.
- **Автоматически 2D**: браузер без WebGL (`fallback('unsupported')`), рендерер не создался или модель не загрузилась (`fallback('error')`). Под картой — строка `role="status"`. Если 2D выбрало само приложение (`view="2d"`), события и строки нет.
- **SSR**: на сервере (без `window` и `document`) рендерится область карты и список объектов, без холста; гидратация идёт без расхождений, WebGL проверяется и холст создаётся в `onMounted`. `view="2d"` на сервере — обычная BaseImageMap. `three` на сервере не вызывается.
- **Состояния слоя**: пока загружается план этажа, область помечена `aria-busy` (озвучивания нет — загрузка короткая); карта без слоёв и ошибка загрузки плана (SVG, картинка, текстура) показываются плашкой поверх сцены (`aria-hidden`), а текст — в единственном `role="status"` под картой: пока видна плашка, эта строка скрыта визуально и остаётся для скринридера. Этаж с ошибкой показывается без плана, остальные работают.
- Свой рендерер (особые настройки WebGL, тесты) — проп `rendererFactory(canvas)`; ошибка внутри фабрики — тоже `fallback('error')`.

## Жизненный цикл и производительность

- Сцена — обычные объекты three.js вне реактивности Vue (`shallowRef`, без глубокой реактивности): выбор, наведение, фильтры и смена этажа перекрашивают материалы и переключают видимость, а не пересобирают сцену. Пересборка — только при смене `data`, и рендерер при этом не создаётся заново.
- Кадр рисуется по требованию (`requestAnimationFrame` по первому изменению — камера, наведение, выбор, размер, тема, данные), постоянного цикла нет; объект под указателем ищется не чаще раза в кадр.
- Плотность пикселей — `min(devicePixelRatio, 2)`.
- Материал один на объект и общий у его частей и контуров, у контуров — общий материал; геометрия объекта строится один раз. Инстансинг не применяется: одинаковых повторяющихся тел на планах нет, каждый объект — своя фигура.
- Размонтирование и замена данных освобождают геометрии, материалы, текстуры и рендерер (`dispose`, `forceContextLoss`), отключают наблюдатель размера и отменяют ожидающий кадр. Ответы загрузки (план, SVG, модель GLB), пришедшие после замены `data` или размонтирования, отбрасываются, а созданное ими освобождается.
- Контейнер нулевого размера (свёрнутая вкладка, `display: none`): размер рендерера не задаётся, камера остаётся конечной; когда размер появляется — размер, камера и новый кадр.

## Ограничения

- Метки `point` и объекты не фокусируются по отдельности (см. «Выбор, клавиатура и скринридер»); скрытые списки объектов есть для всех этажей, но объект другого этажа подсвечивается в сцене только после перехода на его этаж.
- Поддерживаемое подмножество SVG — в разделе «План в SVG»; всё остальное строится без своего эффекта или пропускается, а не падает.
- У этажей из GLB нет скоса: форму модели задаёт её автор. Контур по рёбрам мешей модели рисуется только при явном `scene3d.outline: true` (по умолчанию для GLB выключен, для выдавленных фигур включён).
- Щипок двумя пальцами при `hasOrbit: false` (`touch-action: pan-x pan-y`) браузер может отменить, начав прокрутку страницы: масштаб тогда — кнопками (`hasZoomControls`) или Ctrl / ⌘ с колесом.
- Пропсов `wheelZoom`, `maxZoom`, `initArea` у 3D-карты нет — у камеры свои пределы; метода `resetZoom` нет, есть `resetCamera`.
- Сжатые модели (DRACO, KTX2, meshopt) — только через `configureLoader` приложения.
- Картинка WebGL зависит от GPU и драйвера, поэтому скриншот-тестов 3D-видов в ките нет; снимается только 2D-вид.
- Редактор BaseImageMapEditor остаётся 2D: с `has3dFields` 3D-поля задаются в его панели свойств (высоты, масштаб, сдвиг и поворот — числами, адрес модели и имя узла — текстом), сцену он не показывает; кнопки «Предпросмотр 3D» нет — 3D проверяют в приложении на том же JSON (FOLLOW_UPS, задача map3d-polish).

## Устройство (для разработчиков кита)

- `three` и общее 3D-ядро `src/scene3d` (импорт `@/scene3d/…`) разрешены только в `src/scene3d/**`, папках 3D-компонентов (`BaseImageMap3D`, `BaseFlowMap3D`, `BaseRoadmap3D`) и входах `src/{map3d,flow3d,roadmap3d}.ts` (правило ESLint `no-restricted-imports` и `build/tests/packageBoundaries.spec.ts`); остальной кит three не знает. Пакет `maps` копирует `src/scene3d` целиком (`shared` в `build/packages/packages.json`).
- Общее ядро (`src/scene3d`, один модуль — одна задача, без знания о картах): `renderer/` — рендерер, проверка WebGL, потеря контекста, область рисования, резервный 2D; `loop/` — цикл кадров по требованию (`invalidate`, `animate`, `onBeforeRender`, пауза вне экрана и при скрытой вкладке); `camera/` — поза и кадр (`CameraFraming`), клавиши (Q/E по флагу `hasQuarterTurns`), орбитальная камера `useOrbitCamera`, пресеты; `input/` — указатель (`markerAt`), щипок, луч, навигация стрелками; `overlay/` — проекция и подписи HTML; `theme/` — цвета токенов, тема, палитра; `scene/` — освобождение, кеш ресурсов, свет, загрузчик GLTF; `geometry/` — ленты, текст на земле, контуры, сетка, зерно. Карта переехавшие модули только импортирует: её собственная часть — обёртка `useCameraController` (этаж, режим `layerMode`) и `sceneFrame.ts` (рамка по этажам → `CameraFraming`). Вид и поведение /map3d не менялись.
- Смысловое состояние карты (этаж, выбор, наведение, фильтры, поиск, маршрут, фокус) — модель BaseImageMap; 3D добавляет к ней сцену, камеру и разбор луча и не хранит второй копии состояния.
- `model/` карты: `camera/` — рамка по этажам (`sceneFrame.ts`) и контроллер-обёртка над `useOrbitCamera` ядра; `interaction/` — разбор луча по объектам, клавиатура, наложение (метки, карточка) и список объектов для скринридера; `scene/` — сборка, `geometry/` (SVG, выдавливание, части), `materials/`, `gltf/` (привязка моделей к объектам), маршрут; `viewport/` — сборка сцены этажей, труба маршрута, `load/` — загрузка планов и моделей этажей.
- Проверки в `__tests__/`: `a11y/` (список объектов), `lifecycle/` (утечки, замена данных, нулевой размер), `ssr/`, `sync/` (каталог, этажи, фильтры, 2D ↔ 3D), `model/` (геометрия, камера, SVG, части, контуры).
- Реестр 3D-моделей узлов (`src/scene3d/models`, для BaseFlowMap3D и BaseRoadmap3D; /map3d его не использует). Данные без three: `presets.ts` (35 встроенных моделей — набор, вид, анимация по умолчанию, значок BaseIcon) и `keywords.ts` (основы слов ru/en, подбор по названию и меткам) — их читает и основной вход (`servicesIcon` нотации «сервисы»). Остальное — с three: `registry.ts` (`createModelRegistry`: выбор модели по порядку «поле узла → `models` компонента → модели приложения → `modelResolver` → вид нотации → слова → запасная», сборка, инстансинг встроенных моделей от 8 узлов — по `InstancedMesh` на часть, id узла для луча в `userData.sceneInstanceIds`), `behavior/` (состояния — кольца, светодиод, прозрачность; анимации `play/stop`, уменьшенное движение; дескриптор `Model3DHandle`; вынос узла из инстанса на время анимации), `runtime/` (материалы ролей и общие геометрии на кеше ядра, контекст фабрики, GLB с кешем по адресу), `library/` (`parts.ts` — набор примитивов для фабрик; `server`, `shape`; остальные модели — по файлу на модель, регистрируются строкой в `library/index.ts`), `useModels3D.ts` (`createScene3DModels`, `useScene3DModels`, `defineModel3D`), `modelThumbnails.ts` (миниатюры одним холстом по ножницам). Бюджет детализации: цилиндры ≤ 24 сегментов, кривые ≤ 6, скосы ≤ 2, модель ≤ 2500 треугольников, `server` ≤ 1200; мелкие детали — роль `detail` и группа `lod-detail` (скрывается при клетке < 18 px).
