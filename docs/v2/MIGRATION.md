# Переход на 2.0

Что меняется для приложения при обновлении с 1.x. Документ пополняется по мере выполнения порций [плана](./PLAN.md); к выпуску 2.0 он будет полным.

Внешний вид и значения по умолчанию после редизайна описаны отдельно: [design/CHANGES_FOR_APPS.md](../design/CHANGES_FOR_APPS.md).

## Безопасность (порция 1.1)

### BaseEditor очищает HTML

**Что изменилось.** Раньше HTML из `v-model` вставлялся в редактор как есть и так же возвращался в `update:modelValue`. Теперь он очищается встроенной функцией `sanitizeHtml` в пяти местах:
- при показе `v-model`;
- при вставке из буфера обмена;
- при перетаскивании из другой страницы;
- при выходе из режима кода;
- в `update:modelValue`.

Остаются элементы, которые создаёт сам редактор: абзацы, заголовки, списки, цитаты, код, ссылки, изображения, видео, начертания и цвет. Удаляются:
- скрипты и стили;
- `<iframe>`, `<svg>`, формы;
- обработчики `on*`, атрибуты `class`, `id`, `data-*`;
- CSS-свойства вне списка: цвет, фон, выравнивание, начертание, размеры и скругление медиа.

**Что сделать.**
- HTML, который приложение показывает в редакторе, по-прежнему проверяйте на сервере: клиентскую очистку можно обойти, отправив запрос напрямую.
- Если в содержимом нужны классы или другие элементы, передайте свою функцию очистки: `:sanitize="html => DOMPurify.sanitize(html, config)"`.
- Для полностью доверенного HTML очистку можно отключить: `:sanitize="html => html"`.

### Ссылки в BaseEditor

Кнопка «Ссылка» не вставляет адреса с небезопасной схемой (`javascript:`, `data:`, `vbscript:`) и пишет предупреждение в консоль. Адрес без схемы дополняется: `example.com` → `https://example.com`, `team@example.com` → `mailto:team@example.com`.

### Пункты BaseSideBar с небезопасным адресом

Пункт, у которого строковый `to` содержит небезопасную схему, показывается кнопкой без `href` и не передаётся в `linkComponent`; в консоль один раз выводится предупреждение. Клик по такому пункту по-прежнему эмитит `itemClick`.

## Уведомления и окна (порция 1.2)

### BaseApp, useToast, useOverlay, useConfirm

Новое, ничего менять не нужно. Чтобы вызывать уведомления и окна из кода, оберните приложение в `<BaseApp>` и используйте `useToast()`, `useOverlay()`, `useConfirm()` — пример в README, раздел «BaseApp: уведомления и окна из кода». Отдельный `<BaseNotification ref>` для уведомлений приложения больше не нужен.

### BaseNotification

**Что изменилось.**
- Автозакрытие останавливается, пока указатель над уведомлениями или фокус внутри, и продолжается с остатка времени. Раньше уведомление закрывалось, даже если пользователь читал его или стоял на кнопке.
- Уведомление из `add()` без своего `duration` показывается столько, сколько задано пропом `duration` компонента. Раньше — всегда 3 секунды.
- Длительность больше 2³¹−1 мс (почти 25 дней) ограничивается этим значением. Раньше такое значение переполняло таймер, и уведомление закрывалось сразу.
- `add()` возвращает id уведомления. Тип id — `NotificationId` (`string | number`), раньше `number`: так же типизированы `NotificationItem.id` и аргумент `remove()`.
- Новое: `isPersistent` (без автозакрытия), `actions` (кнопки под текстом), управляемый список `items` и событие `remove(id)`, ключ `actions` в `customClass`.

**Что сделать.**
- Если код сохраняет id уведомления в переменную типа `number`, поменяйте тип на `NotificationId`.
- Тесты, которые ждут автозакрытия, не должны держать указатель или фокус над уведомлением.
- Уведомлениям, которые должны закрываться быстрее компонента по умолчанию, передайте `duration` в `add()`.

### BaseModal

Новое, ничего менять не нужно: `dialogRole` (`dialog` или `alertdialog`), `ariaDescribedby`, событие `after-leave` после анимации закрытия.

## Тема, настройки и ссылки (порция 1.3)

### BaseBreadcrumbs: крошки — ссылки

**Что изменилось.** Раньше крошка с `to` была кнопкой и только эмитила `navigate(url)`, а крошка с `href` открывалась через `window.open`. Теперь крошка с адресом — ссылка:
- `to` рендерит компонент ссылок приложения: проп `linkComponent`, `createUiKitPlugin({ linkComponent })` или RouterLink, если подключён vue-router. Без роутера — `<a href>`, и клик переходит по адресу с перезагрузкой страницы;
- `href` — `<a href>`, по умолчанию в новой вкладке, как раньше. Новое поле `target` у крошки меняет это;
- крошка без адреса — кнопка с событием `item-click`, как раньше;
- `navigate(url)` приходит при клике по ссылке, но переход выполняет сама ссылка;
- ссылка «домой» (`showHome`) тоже ссылка, её клик теперь эмитит и `item-click`.

**Что сделать.**
- Если приложение переходило по `@navigate="router.push"`, уберите обработчик: с vue-router крошки переходят сами. Без vue-router передайте свой компонент ссылок в `linkComponent`.
- Тесты, которые искали крошки по роли `button`, ищите по роли `link`.

### BaseSideBar: компонент ссылок из приложения

**Что изменилось.** Без пропа `linkComponent` пункты рендерились `<a href>` с перезагрузкой страницы. Теперь компонент берётся из `createUiKitPlugin({ linkComponent })` или RouterLink подключённого vue-router; без них — `<a href>`, как раньше. Внешний адрес в `to` (`https://…`, `mailto:`) всегда рендерится `<a href>`, а не RouterLink.

**Что сделать.** Ничего, если переходы по пунктам должны идти через роутер. Чтобы сохранить `<a href>`, передайте `link-component="a"`.

### Значения по умолчанию компонентов

**Что изменилось.** Значения props по умолчанию теперь можно задать для всего приложения: `createUiKitPlugin({ defaults: { global: { sizeScale: 90 }, BaseButton: { variant: 'soft' } } })`. Для этого 25 компонентов с вариантами оформления объявляют `variant: 'default'` по умолчанию, раньше — `undefined`. Вид не меняется: `default` и раньше означал отсутствие модификатора.

**Что сделать.** Ничего. Если код сравнивал `props.variant` дочернего компонента с `undefined`, сравнивайте с `'default'`.

### Новое

- `data-theme="system"` — тема как в системе; `useColorMode()` и `createColorMode()`; кнопка `BaseColorModeButton`.
- `BaseLink` — ссылка на маршрут или внешний адрес с проверкой схемы.
- `createUiKitPlugin({ defaults, icons, linkComponent })`, `createIconPlugin({ icons })`.
- Иконки `sun` и `moon` в спрайте.

## Языки (порция 1.4)

### Строки кита — из словаря текущего языка

**Что изменилось.** Строки интерфейса кита вынесены в словари `ru` и `en` (`src/locales`). Константы `UI_TEXT`, `UI_ARIA`, `UI_TOUR`, `UI_FILTER`, `UI_CALENDAR`, `UI_COLOR_PICKER`, `UI_RATING`, `UI_CHAT_TEXT`, `UI_EDITOR`, `TABLE_TEXT` стали представлениями словаря: возвращают строку текущего языка. Их тип — `string`, а не конкретная строка. По умолчанию язык русский, строки те же.

У props со строкой по умолчанию (`placeholder` у BaseSelect и BaseSearch, `label` у BaseLoader и BaseColorModeButton, `confirmLabel`, `cancelLabel`, `resetLabel`, `buttonText`, `emptyText` у BaseTable) значение по умолчанию теперь `undefined`: строка текущего языка подставляется при рендере.

**Что сделать.** Ничего, если приложение на русском. Для английского — `createUiKitPlugin({ locale: 'en' })` или `<BaseApp locale="en">`. Если код читал такой проп компонента через ref и ждал строку по умолчанию, берите строку из `useLocale().messages`.

### Числа и множественное число

**Что изменилось.**
- `formatFileSize` пишет дробь по правилам языка: `1,5 КБ` вместо `1.5 КБ`; по-английски — `1.5 KB`.
- Строка страниц пагинации — с разделителем разрядов: `1 001–2 000 из 5 000`.
- Множественное число по правилам языка: «3 участника» вместо «3 участников» в BaseChat, «Выбрано: 4 даты» вместо «Выбрано: 4 дат» в BaseDatePicker.

**Что сделать.** Обновите тесты и снимки, которые сравнивали эти строки.

### Календарь

**Что изменилось.** Без пропов `locale` и `firstDayOfWeek` календарь и выбор даты берут формат дат и первый день недели из языка кита. По-русски — как раньше (`ru-RU`, понедельник); по-английски — `en-US` и воскресенье.

**Что сделать.** Чтобы оставить понедельник в английском интерфейсе, передайте `first-day-of-week="1"` или свой язык `defineLocale(en, { firstDayOfWeek: 1 })`.

### Прочее

- `useTableToolbar().filterOperatorOptions` — `ComputedRef`: подпись «Содержит» следует языку.

## Слои оверлеев (порция 1.5)

### Escape и клик снаружи — только верхнему слою

**Что изменилось.** Окна, боковые панели, выпадающие списки, меню, подсказки, тур и просмотр изображения стали слоями общего стека (`useLayer`). Раньше каждый компонент слушал `document` сам, и одно нажатие Escape закрывало всё открытое сразу: список и окно, в котором он открыт. Теперь:
- Escape получает только верхний открытый слой с обработчиком Escape. Из окна с открытым списком первое нажатие закрывает список, второе — окно. Если на экране видна подсказка, первое нажатие скрывает её.
- Нажатие, для которого элемент уже вызвал `event.preventDefault()`, и Escape, отменяющий ввод через IME, слои не обрабатывают.
- Нажатие мыши в панели слоя, открытого позже (список в поповере, выбор даты в окне), не считается нажатием снаружи для слоёв под ним.
- Escape у панели эмодзи в чате больше не закрывает окно или боковую панель, в которых открыт чат.

**Что сделать.**
- Если приложение закрывало окно и открытый в нём список одним Escape и тесты это проверяют — ждите два нажатия.
- Свой обработчик Escape внутри окна кита (поле с отменой ввода, свой список) должен вызывать `event.preventDefault()`, иначе то же нажатие закроет и окно.
- Свои всплывающие элементы подключайте через `useEscapeKey` и `useClickOutside` — так они встанут в общий стек.

### useClickOutside и useEscapeKey

**Что изменилось.**
- `useClickOutside` и `useEscapeKey` регистрируют слой: слушатели на `document` общие для всех слоёв и снимаются, когда размонтирован последний. Слой регистрируется при монтировании компонента, как и раньше.
- `useClickOutside` по-прежнему реагирует на `mousedown`; нажатие внутри слоёв, открытых позже, теперь не вызывает `callback`. «Внутри» определяется по пути события (`composedPath`): работает в Shadow DOM и когда обработчик на элементе успел удалить цель нажатия из DOM.

**Что сделать.** Тесты, которые проверяли `document.addEventListener` или `removeEventListener` этих composables, перепишите на поведение: событие `mousedown` или `keydown` и результат.

### useDropdownPosition: переворот и сдвиг у края окна

**Что изменилось.**
- Если на выбранной стороне не хватает места, а на противоположной хватает, панель открывается с противоположной стороны; вдоль края окна она сдвигается, оставляя 8px (`VIEWPORT_MARGIN`). Проп `position` не меняется, фактическая сторона — в новом `placement`.
- `coords` — теперь левый верхний угол панели. Раньше это была точка привязки у триггера, а `panelStyle` выравнивал панель через `right`, `bottom` и `transform`.
- `panelStyle` содержит только `top`, `left`, `maxHeight` и `width` (при `matchWidth`).
- Слушатели прокрутки и изменения окна есть только у открытой панели; размер панели отслеживает `ResizeObserver`.

**Что сделать.**
- Если приложение само вызывало `useDropdownPosition`, не добавляйте к панели `transform` для выравнивания: координаты уже учитывают размер панели.
- Тесты и снимки экрана с панелями у края окна: панель может оказаться с другой стороны триггера.
- В jsdom нужен мок `ResizeObserver` (как и для BaseTable, BaseTabs, BaseSlider).

### Контейнер слоёв и тема панелей

**Новое.**
- `createUiKitPlugin({ teleportTo })` и проп `teleportTo` у `BaseApp` задают, куда телепортируются окна, панели, подсказки и уведомления (по умолчанию `body`). Нужен, например, в полноэкранном режиме.
- Выпадающие панели, подсказки и контекстные меню редактора и чата берут `data-theme` ближайшего предка триггера: панель из тёмного блока на светлой странице — тёмная.
- Composables `useLayer`, `useLayerIndex`, `getOpenLayers`, `useTeleportTarget`, `useInheritedTheme`, ключ `TELEPORT_TARGET_KEY`.

**Что сделать.** Ничего. Если приложение ставило `data-theme` на телепортированные панели через `panelClass` или стили, это можно убрать.

### z-index: порядок открытия и токены

**Что изменилось.** Раньше z-index был задан числами по типу компонента, и при равных значениях порядок наложения решало место якоря Teleport в DOM — момент монтирования компонента, а не открытия. Окно из `App.vue` оказывалось под боковой панелью страницы, а окно, открытое из меню, — под меню (1100 против 1000). Теперь окна, боковые панели, тур, окно поиска, выпадающие панели, календарь и контекстные меню редактора и чата — один стек: z-index = `--rise-z-overlay` + место слоя среди открытых (`--rise-layer-index`). Слой, открытый позже, всегда выше.

| Токен | Значение | Компоненты |
|---|---|---|
| `--rise-z-overlay` | 1000 | основа стека: BaseModal, BaseSlideover, BaseTour, окно BaseSearch, BaseDropdown (и BaseSelect, BasePopover, BaseSearch), панель BaseDatePicker, меню BaseEditor и BaseChat; подменю BaseMegaMenu (без места в стеке, как раньше — 1000) |
| `--rise-z-toast` | 2000 | BaseNotification |
| `--rise-z-tooltip` | 3000 | BaseTooltip |
| `--rise-z-max` | 9999 | просмотр изображения BaseImage |

Что сдвинулось:
- выпадающие панели, календарь и контекстные меню — 1000 + место вместо 1100: над окном, только если открыты позже него (список в окне — как раньше, над окном);
- подсказка — 3000 вместо 9999: теперь под просмотром изображения.

**Что сделать.**
- Если у приложения свои слои между этими значениями (липкая шапка, чат поддержки), переопределите токены в `:root`, а не z-index в стилях компонентов.
- Свой телепортированный элемент, который должен вставать в общий порядок, — `useLayerIndex` и `z-index: calc(var(--rise-z-overlay) + var(--rise-layer-index, 0))`.

## Меню и тултипы (порция 1.6)

### BaseTooltip

**Что изменилось.**
- Обёртка триггера — `span` вместо `div` (подсказку можно ставить внутри абзаца и строки таблицы). Классы прежние.
- Пока подсказка на экране, первый фокусируемый элемент в слоте получает `aria-describedby` с её id.
- На подсказку можно навести указатель, и она не пропадает (WCAG 1.4.13): у подсказки больше нет `pointer-events: none`.
- У края окна подсказка переворачивается на противоположную сторону и сдвигается внутрь; класс `base-tooltip-popup--{сторона}` — фактическая сторона.
- Пустой `text` подсказку не показывает.

**Что сделать.**
- Стили и тесты, которые искали `div.base-tooltip`, — на класс без тега.
- Если подсказка перекрывала кликабельные элементы и клик проходил сквозь неё, теперь клик попадёт в подсказку: поставьте подсказку с другой стороны (`position`).

### BasePopover

**Что изменилось.**
- Первый фокусируемый элемент слота `trigger` получает `aria-haspopup="dialog"`, `aria-expanded`, `aria-controls` и id (если своего нет); содержимое — `role="dialog"` с именем кнопки.
- Закрытие повторным кликом по кнопке эмитит `close`, как Escape и клик снаружи (раньше — только `update:isOpen`).

**Что сделать.** Если обработчик `close` не ждал закрытия кнопкой, проверьте его.

### BaseMegaMenu: листья — ссылки

**Что изменилось.** Узел без `children` с `to` или `href` — ссылка (`BaseLink`): RouterLink приложения (из `linkComponent` плагина или vue-router) или `<a href>`. Переход выполняет ссылка, и её можно открыть в новой вкладке. События `navigate` (с адресом) и `item-click` остаются. Раньше узел был `div role="button"`, а для `to` переход выполняло приложение по событию `navigate`; для `href` кит вызывал `window.open`.

**Что сделать.** Если приложение переходило по маршруту в обработчике `navigate` для пунктов с `to`, уберите переход: теперь его делает ссылка. Верхние пункты `layout="dropdown"` и заголовки колонок пока кнопки — для них `navigate` работает по-прежнему.

### Телепорты с defer

**Что изменилось.** Окна, панели и подсказки монтируют `<Teleport defer>`: цель телепорта ищется после монтирования приложения. Контейнер слоёв (`teleportTo`) может стоять в том же шаблоне, что и меню, — раньше Vue его не находил. Открытое при монтировании окно появляется в том же цикле монтирования.

**Что сделать.** Ничего. Тесты, которые искали телепортированное содержимое сразу после `mount`, работают; после смены состояния, как и раньше, нужен `await nextTick()`.

### Новое

- `BaseDropdownMenu` — меню у кнопки по APG Menu Button: пункты, флажки, переключатели, подписи групп, разделители, подменю, ссылки, сочетания клавиш; стрелки, Home/End, поиск по буквам.
- `BaseContextMenu` — меню по правому клику, клавише «Меню» и Shift+F10.
- `BasePopconfirm` — вопрос у кнопки перед действием (`confirm`, `cancel`, `isDanger`).
- `useTriggerAttributes` — ARIA-атрибуты на кнопке из слота; `findTypeaheadIndex`, `toMenuGroups` — утилиты меню; `resolveTooltipPlacement`, `calcTooltipShift` — переворот и сдвиг подсказки.

## Новые утилиты

| Функция | Назначение |
|---|---|
| `sanitizeHtml(html)` | Очистка HTML по списку разрешённых элементов, атрибутов и CSS-свойств |
| `escapeHtml(text)` | Экранирование текста для вставки в HTML |
| `normalizeLinkUrl(input)` | Приведение введённого адреса к ссылке (`example.com` → `https://example.com`) |
| `isExternalUrl(url)` | Адрес вне приложения (со схемой или `//`): открывается `<a href>`, а не RouterLink |
