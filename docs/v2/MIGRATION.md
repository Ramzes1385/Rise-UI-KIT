# Переход на 2.0

Что меняется для приложения при обновлении с 1.x. Сначала — порядок перехода и краткий список изменений, дальше — подробности по областям: что изменилось и что сделать.

Внешний вид и значения по умолчанию после редизайна — [design/CHANGES_FOR_APPS.md](../design/CHANGES_FOR_APPS.md), изменения по компонентам — [design/VISUAL_CHANGES.md](../design/VISUAL_CHANGES.md).

## Порядок перехода

1. Обновите пакет: `npm install @ramzes1385/rise-ui-kit@^2`. Нужен Vue 3.5 или новее.
2. Импорты: подпуть `@ramzes1385/rise-ui-kit/plugins` и namespace `plugins` удалены — `createIconPlugin` импортируйте из `@ramzes1385/rise-ui-kit/icons`. Видеоплеер `BaseMediaPlayer` — только из `@ramzes1385/rise-ui-kit/media`.
3. Если приложение вызывает `calcTotalColumns`, `resolveTooltipPlacement` или `calcTooltipShift` из `utils`, передайте поля объектом — раздел [«Утилиты: объект вместо длинного списка параметров»](#утилиты-объект-вместо-длинного-списка-параметров-порция-с5).
4. Типы: id уведомлений — `NotificationId` (`string | number`) вместо `number` (раздел [«Уведомления и окна»](#уведомления-и-окна-порция-12)).
5. Стили: компоненты читают только токены `--rise-*`, переменные 1.x (`--color-accent`…) их больше не перекрашивают. Свои слои с `z-index` согласуйте с токенами `--rise-z-*` — раздел [«Слои оверлеев»](#слои-оверлеев-порция-15).
6. Язык: по умолчанию русский, как раньше; английский — `createUiKitPlugin({ locale: 'en' })` или `<BaseApp locale="en">`.
7. `BaseEditor` очищает HTML: если в содержимом нужны классы или другие элементы, передайте свою функцию `sanitize` — раздел [«Безопасность»](#безопасность-порция-11).
8. Ссылки: `BaseBreadcrumbs`, `BaseSideBar`, `BaseMegaMenu` и `BaseTree` переходят по `to` сами (RouterLink приложения или `<a href>`) — уберите `router.push` из обработчиков их событий.
9. Формы: уберите `for` у `BaseFormField` вокруг контролов кита, атрибуты `name`, `autocomplete`, `data-testid` передавайте полям через `inputAttrs`, ручную блокировку контролов по `isLoading` формы можно убрать — раздел [«Формы»](#формы-порция-18).
10. Тесты приложения: роли и разметка стали ближе к образцам WAI-ARIA — крошки ищутся по роли `link`, поле `BaseSearch` — `combobox`, `BaseSwitch` — `switch`, узлы `BaseTree` проходятся стрелками, а не Tab; обёртка `BaseTooltip` — `span`; Escape закрывает только верхний слой. Пройдите разделы ниже по компонентам, которые использует приложение.
11. Скриншоты приложения обновите после просмотра: изменились высота контролов, отступы и цвета ([design/CHANGES_FOR_APPS.md](../design/CHANGES_FOR_APPS.md)).
12. По желанию: `BaseApp` с `useToast`, `useOverlay` и `useConfirm` — уведомления и окна из кода; `useColorMode` и `BaseColorModeButton` — светлая, тёмная и системная тема.

## Коротко: что нового и что изменилось

**Редизайн.** Все компоненты переведены на дизайн-токены `--rise-*` и новый визуальный язык в духе Nuxt UI: нейтральная палитра, тонкие рамки, контролы высотой 32px, фокус-кольцо, тёмная тема на тех же токенах. Публичный API не менялся, но изменились визуальные значения по умолчанию (например, отступы `BaseButton` — 5px 10px вместо 10px 20px, `BaseCard` — 16px 20px вместо 24px 48px) и часть внутренней разметки. Что заметит приложение — [design/CHANGES_FOR_APPS.md](../design/CHANGES_FOR_APPS.md); изменения по компонентам — [design/VISUAL_CHANGES.md](../design/VISUAL_CHANGES.md); правила дизайн-системы — [design/DESIGN_SYSTEM.md](../design/DESIGN_SYSTEM.md).

Исправления по итогам аудита и новые возможности. Новые props и опции необязательны. Удалены подпуть `/plugins` и namespace `plugins`, три утилиты таблицы и подсказок принимают объект — разделы [«Структура исходников»](#структура-исходников) и [«Утилиты: объект вместо длинного списка параметров»](#утилиты-объект-вместо-длинного-списка-параметров-порция-с5). Ниже — то, что может заметить приложение.

**Безопасность**

- `BaseEditor` очищает HTML по умолчанию (проп `sanitize`, функция `sanitizeHtml`): при показе `v-model`, вставке из буфера и перетаскивании, выходе из режима кода и в `update:modelValue`. Разметка вне списка разрешённых элементов, атрибутов и CSS-свойств удаляется. Кнопка «Ссылка» не вставляет адреса с небезопасной схемой (`javascript:`, `data:`), а адрес без схемы (`example.com`) дополняет до `https://`.
- `BaseSideBar`: пункт со строковым `to` небезопасной схемы показывается кнопкой без `href`, в консоль — предупреждение.
- Новые утилиты: `sanitizeHtml`, `escapeHtml`, `normalizeLinkUrl`.

**Уведомления и окна из кода**

- Новый `BaseApp` — корень приложения: показывает уведомления `useToast()` и окна `useOverlay()` / `useConfirm()` (см. [«BaseApp: уведомления и окна из кода»](../../README.md#baseapp-уведомления-и-окна-из-кода) в README). Новый компонент `BaseConfirm` — окно подтверждения с `role="alertdialog"`.
- `BaseNotification`: автозакрытие останавливается, пока указатель над уведомлениями или фокус внутри, и продолжается с остатка времени (WCAG 2.2.1). Новые props `isPersistent` (без автозакрытия), `actions` (кнопки вроде «Отменить»), `items` (управляемый список) и событие `remove(id)`. `add()` возвращает id; уведомление из `add()` без своего `duration` берёт `duration` компонента; длительность больше 2³¹−1 мс ограничивается этим значением.
- `BaseModal`: props `dialogRole` (`dialog` или `alertdialog`) и `ariaDescribedby`, событие `after-leave` после анимации закрытия; `ariaLabel` — имя окна без видимого заголовка (порция 3.1а).

**Тема, настройки и ссылки**

- Тема «как в системе»: `data-theme="system"` включает тёмные токены при `prefers-color-scheme: dark`. `useColorMode()` переключает светлую, тёмную и системную тему и запоминает выбор; `BaseColorModeButton` — кнопка тёмной темы для шапки.
- `createUiKitPlugin` принимает `defaults` (значения props по умолчанию для всех компонентов или для одного), `icons` (замена иконок кита своими) и `linkComponent` (RouterLink, NuxtLink). Компоненты с вариантами оформления теперь объявляют `variant: 'default'` по умолчанию — вид не меняется, но вариант можно задать через `defaults`.
- Новый `BaseLink`: маршрут (`to`) или внешний адрес (`href`), небезопасные схемы не попадают в `href`, для `target="_blank"` — `rel="noopener noreferrer"` и подсказка для скринридера.
- `BaseBreadcrumbs`: крошки — настоящие ссылки (RouterLink приложения или `<a href>`), а не кнопки; крошка без адреса — кнопка с `item-click`. Новые `linkComponent` и `target` у крошки.
- `BaseSideBar`: без пропа `linkComponent` берёт компонент из плагина или RouterLink подключённого vue-router; внешний адрес в `to` (`https://…`) открывается обычной ссылкой.

**Языки**

- Строки интерфейса кита — в словарях `ru` (по умолчанию) и `en`. Язык задают `createUiKitPlugin({ locale })`, `<BaseApp locale>` или `setLocale()`; `useLocale()` возвращает язык и форматирование по его правилам. Свой язык — `defineLocale(en, { … })`.
- Константы `UI_TEXT`, `UI_ARIA`, `UI_CHAT_TEXT` и другие со строками возвращают строку текущего языка, а шаблоны перерисовываются при его смене.
- Календарь и выбор даты берут формат дат и первый день недели из языка кита (по-русски — как раньше), если не заданы `locale` и `firstDayOfWeek`.
- Числа — через `Intl`: размер файла по-русски с запятой (`1,5 КБ`), большие номера страниц с разделителем разрядов. Множественное число по правилам языка: «3 участника», «Выбрано: 4 даты».

**Слои оверлеев**

- Escape и клик снаружи получает только верхний открытый слой: из окна с открытым списком первое нажатие Escape закрывает список, второе — окно; клик в панели вложенного списка не закрывает внешнюю. Нажатия, для которых элемент вызвал `preventDefault()`, и Escape при вводе через IME не обрабатываются.
- Порядок наложения — порядок открытия: окно, открытое из меню, — над меню, список в окне — над окном. z-index задают токены `--rise-z-overlay`, `--rise-z-toast`, `--rise-z-tooltip`, `--rise-z-max`; подсказка теперь 3000 (было 9999).
- Выпадающие панели у края окна открываются с противоположной стороны и сдвигаются внутрь окна.
- Контейнер слоёв — `createUiKitPlugin({ teleportTo })` и `<BaseApp teleport-to>`. Панели, подсказки и контекстные меню берут `data-theme` блока, из которого открыты.
- Подробности и что сделать приложению — раздел [«Слои оверлеев»](#слои-оверлеев-порция-15).

**Меню и подсказки**

- Новые компоненты: `BaseDropdownMenu` (меню у кнопки по APG: флажки, переключатели, подменю, поиск по буквам), `BaseContextMenu` (меню по правому клику, клавише «Меню» и Shift+F10), `BasePopconfirm` (вопрос у кнопки).
- `BaseTooltip`: элемент описан подсказкой (`aria-describedby`), на подсказку можно навести указатель, у края окна она переворачивается и сдвигается, пустой `text` не показывается. Обёртка — `span` вместо `div`.
- `BasePopover`: кнопке ставятся `aria-haspopup`, `aria-expanded` и `aria-controls`, панель — диалог с именем кнопки; закрытие повторным кликом эмитит `close`.
- `BaseMegaMenu`: листья с `to` или `href` — ссылки (`BaseLink`): RouterLink приложения или `<a href>`.
- Окна, панели и подсказки монтируют телепорт после приложения (`defer`): контейнер слоёв может стоять в том же шаблоне, что и меню.
- Подробности — раздел [«Меню и тултипы»](#меню-и-тултипы-порция-16).

**Выбор и дерево**

- `BaseSelect`: закрытое поле открывается буквой и сразу подсвечивает опцию по началу подписи (повтор буквы — следующая опция, пробел во время поиска — часть слова); Home/End открывают список на первой и последней опции. В поле с поиском (`isSearchable`) буквы вводятся в поле.
- `BaseSearch`: поле — `role="combobox"` со списком результатов `role="listbox"` (`aria-expanded`, `aria-controls`, `aria-activedescendant` подсвеченного результата); число найденного объявляется через `role="status"` («Найдено 3 результата»).
- `BaseTree` по образцу APG Tree View: корень — `role="tree"` (имя — новый проп `ariaLabel`), узлы — `treeitem` с `aria-level`, `aria-setsize`, `aria-posinset`, `aria-expanded`; выбор — `aria-selected` (single) или `aria-checked` (multiple). В порядке Tab один узел; по дереву — стрелки, Home/End, `*` (раскрыть соседей), буквы (поиск по началу подписи), Enter и пробел. Ветки раскрываются с клавиатуры и в режимах выбора.
- `BaseTree`: флажок в режиме `multiple` — только вид (`inert`): не получает фокус и не объявляется отдельно, клик по нему — клик по узлу.
- `BaseTree`: узел с `to` или `href` — ссылка `BaseLink` (у узла новое поле `target`). Клик по подписи и Enter переходят по ней, в режиме `single` узел становится выбранным; раскрытие не меняется.
- Подробности — раздел [«Выбор и дерево»](#выбор-и-дерево-порция-17).

**Формы**

- `BaseFormField` передаёт контролу кита внутри (BaseInput, BaseTextarea, BaseSelect, BaseCheckboxGroup) свой id, описание, ошибку и обязательность: подпись обёртки — имя поля (`for` не нужен), описание или ошибка — его `aria-describedby`, ошибка обёртки красит поле. Новый проп `name` — ошибка из проверки `BaseForm` по схеме.
- `BaseInput`, `BaseTextarea`: новые `ariaLabel` (имя без видимой подписи) и `inputAttrs` (`name`, `autocomplete`, `inputmode`, `aria-*`, `data-*`, свой `id` — на нативное поле). Звёздочка обязательного поля скрыта от скринридера — обязательность объявляет `aria-required`.
- `BaseForm`: `schema` (Standard Schema — Zod, Valibot, ArkType) и `state` — проверка перед `submit`, событие `invalid`, фокус на первом поле с ошибкой, `validate()` и `reset()` через ref; `submit` получает данные вторым аргументом. Отключённая или отправляемая форма блокирует и кастомные контролы кита (BaseSelect, BaseRange, BaseRating, BaseFileUpload, BaseEditor).
- `BaseCheckbox`: частичный выбор `isIndeterminate`. Новый компонент `BaseCheckboxGroup` — группа флажков с массивом в `v-model` и флажком «Выбрать все».
- Подробности — раздел [«Формы»](#формы-порция-18).

**Новые компоненты**

- `BaseKbd`, `BaseTimeline`, `BaseAvatarGroup`, `BaseUser`, `BaseButtonGroup`, `BaseSplitButton`, `BaseToolbar` (APG Toolbar), `BaseFab`, `BaseInplace` — отображение и действия (порция 2.2).
- `BaseLayout`, `BaseHeader`, `BaseFooter`, `BaseContainer` — каркас страницы со ссылкой «Перейти к содержимому»; `BaseSplitter` (APG Window Splitter), `BaseScrollArea`, `BaseDrawer`, `BaseBackTop`, `BaseInfiniteScroll` — каркас и прокрутка (порция 2.3).
- `BaseVirtualList` — список на тысячи строк (в DOM только видимые) и composable `useVirtualList`; виртуальная прокрутка в `BaseTable` (`isVirtual`, `rowHeight`) и `BaseTree` (`isVirtual`, `height`, `itemSize`) — порция 2.4.
- `BaseInputNumber` — число с кнопками −/+ по образцу APG Spinbutton; `BaseAutocomplete` — поле с подсказками (APG Combobox), свой вариант и загрузка с сервера; `BaseTimePicker` — время из списка с шагом или набором «930» → 09:30; `BaseInputTags` — поле тегов; `BaseSegmented` — переключатель сегментами на нативных radio. Все подключаются к `BaseFormField` и `BaseForm`.
- `BasePhoneInput` — телефон: выбор страны в списке с флагами (порция Н.5) и маска номера, `v-model` — `+79161234567`, вставка «+375 29…» или «8 916…» сама выбирает страну; `BaseMoneyInput` — сумма с разрядами при вводе и знаком валюты по `currency`, округление и границы после ухода из поля (порция 4.17а).
- `BaseRequisiteInput` — реквизиты с проверкой контрольных чисел: ИНН, КПП, ОГРН, ОГРНИП, БИК, расчётный и корреспондентский счёт (вместе с БИК), СНИЛС; те же проверки — функциями `isValidInn` и др. `BaseAddressInput` — адрес с подсказками из подключаемого источника, готовый адаптер DaData (порция 4.17б).
- `BaseBottomNav` — нижние вкладки для телефона и PWA: 3–5 пунктов со значком и подписью, `v-model` с `aria-current="page"`, ссылки или кнопки, счётчики BaseBadge, безопасная зона, `hideOnScroll` (задача new-bottom-nav, раздел [«Нижняя навигация»](#нижняя-навигация-new-bottom-nav)).

**Медиа**

- `BaseMediaPlayer` — видеоплеер со своей панелью поверх `<video>`: перемотка с загруженными отрезками, время, звук и громкость, полноэкранный режим, горячие клавиши в любой раскладке, ошибка с «Повторить», отказ автозапуска (порция 4.1); меню скорости и качества, название и логотип поверх кадра, большая кнопка «Воспроизвести», индикатор загрузки, широкий экран, `v-model` позиции, громкости, звука, скорости и широкого экрана (порция 4.2); двойной клик по краю кадра — ∓10 с, удержание — ×2, меню по правому клику (повтор, ссылка и ссылка с таймкодом, «Сообщить о проблеме» — событие `report`, техническая информация), запоминание позиции (`storage-key`) и старт с `?t=` из адреса (порция 4.3); субтитры .vtt и .srt: выбор дорожки, клавиша C, размер, цвет, фон, перетаскивание блока мышью, свой файл зрителя из меню или перетаскиванием на плеер (порция 4.4); озвучки отдельными аудиофайлами синхронно с видео и дорожки внутри файла там, где их видит браузер (порция 4.5); потоки HLS через hls.js, который подключает приложение: качество «Авто» и вручную, озвучки и субтитры потока (порция 4.6); сезоны и серии, следующая серия с отсчётом, главы на шкале и «Пропустить опенинг» (порция 4.7); аудиорежим — компактная панель без кадра для аудиофайлов (порция 4.14); панель по прежнему плееру VideoStack: иконки, отдельные кнопки, меню без каскадов, панель скорости как в YouTube (правки П3 и П3б); шкала с цветными отрезками глав, превью кадра при наведении и интро и аутро отдельными роликами (правка П4); оверлеи VideoStack — пауза, перемотка, загрузка, ошибка, карточка следующей серии, «Данные для отладки» с логом событий и отчётом, обложка с анимацией и видео-обложкой (правка П5); **Поведение**

- `BaseInput`: курсор после маски и фильтра `allowedChars` ставится сразу, а не в следующем кадре: при быстром вводе он больше не переносится назад (раньше «12ab34» с фильтром цифр могло дать «1243»).
- Оверлеи с блокировкой прокрутки (Modal, Slideover, Tour, зум изображения, оверлей `BaseSearch` в режимах `modal`/`sidebar`) используют общий счётчик: закрытие одного слоя не разблокирует страницу, пока открыт другой.
- `BaseNotification`: `duration: 0` и некорректные значения заменяются значением по умолчанию (3000 мс); раньше уведомление исчезало почти сразу.
- `BaseImage`: `<source>` AVIF/WebP добавляются только при явных `convertToAvif`/`convertToWebp` (новый проп `convertToAvif`, по умолчанию `false`); раньше AVIF и WebP запрашивались для любого локального src. Таймаут загрузки `loading="lazy"` отсчитывается с момента попадания в зону видимости.
- Иконки: путь к спрайту задаётся `createUiKitPlugin({ iconSpritePath })` или `createIconPlugin({ spritePath })`; спрайт доступен как подпуть пакета `@ramzes1385/rise-ui-kit/icons.svg`.
- `BaseForm`: во время `isLoading`/`isDisabled` поля блокируются через `<fieldset disabled>` (раскладка контента не меняется — у fieldset `display: contents`), после разблокировки фокус возвращается на прежнее поле. Кастомные контролы кита (`BaseSelect`, `BaseRange`, `BaseRating`, `BaseFileUpload`, `BaseEditor`) блокируются вместе с формой через её контекст (раздел [«Формы»](#формы-порция-18)). Заблокированные поля не попадают в FormData: если данные собираются после выставления `isLoading` (например, после `await`), соберите FormData до перевода формы в loading.
- `BaseFormField`: `validate()` больше не сообщает ложное «Обязательное поле» — обязательность проверяет сам контрол/форма, `isRequired` отвечает за звёздочку.
- `BaseRadio`: слот `option` заменяет только подпись — нативный input и кружок рендерятся всегда.
- `BaseInput` с маской: в readonly/disabled поле Backspace/Delete ничего не удаляют; маски с несколькими литералами в начале (`+7 (`) набираются посимвольно. Известное ограничение осталось: если первая набранная цифра совпадает с цифрой префикса маски (`+7 (###)…` и ввод «7», `8 (###)…` и ввод «8»), она поглощается префиксом.
- `BaseRating`: клик всегда привязывается к `step` (раньше при `isHoverSmooth` сохранялось дробное значение вроде 2.65).
- `BaseColorPicker`: в модель уходит точный HEX пресета/ввода (раньше искажался при пересчёте через HSV).
- `BaseRange`: управление с клавиатуры эмитит `change`; шаг 0.1 не даёт хвостов плавающей точки.
- `BaseSearch`: новый проп `isRemote` — результаты с сервера показываются без клиентской фильтрации; подсветка сбрасывается при изменении списка.
- `BaseSlider`: автопрокрутка останавливается при наведении и фокусе внутри, отключается при `prefers-reduced-motion`. С `isZoomable` клик по слайду открывает зум (раньше проп не работал), а перетаскивание слайда мышью зум не открывает.
- `BaseDropdown`: клик в поле ввода внутри выпадающего списка оставляет фокус в поле (поиск в `BaseSelect` работает мышью); при закрытии (Escape, выбор опции) фокус из поля ввода панели возвращается на триггер (например, на поле `BaseSelect`), а не теряется на body.
- `BaseTable`: пустые и нераспознанные значения при сортировке всегда в конце, числовые строки сравниваются как числа; даты в колонках `sortType: 'date'` распознаются как ISO 8601-строки, объекты `Date` и числовые timestamp, а строки вида ДД.ММ.ГГГГ датами не считаются (сортируются как нераспознанные, после корректных); «Выбрать все» при поиске работает по найденным строкам; `columns-change` отдаёт копии колонок, изменения `isHidden`/`width` из props применяются после монтирования.
- `BaseDatePicker`: настройки `minDate`/`maxDate`/`disabledWeekdays`/`showTime`/`showWeekNumber` снова доходят до календаря (регрессия 1.2.2); при нескольких месяцах (`isMultiMonth`) и `showTime` блок времени показывается один раз — под первым месяцем. `BaseCalendar`: AM/PM считается из часов, ввод времени ограничен диапазоном; `v-model:is-am` при PM-значении эмитит `update:isAm` при монтировании.
- `BaseEditor`: автоконвертация набранной разметки ограничена парой простых inline-тегов без атрибутов (`<b>`, `<i>`, `<u>`, `<s>`, `<code>` …), остальное остаётся текстом; в `isReadonly` меню медиа не открывается.
- `BaseChat`: из панели «Информация» убраны демо-данные (описание, телефон, e-mail) — описание передаётся новым пропом `description`; при закрытии поиска запрос сбрасывается; черновик и вложения сохраняются при входе в режим выделения.
- `BaseFileUpload`: в одиночном режиме новый файл заменяет выбранный (раньше накапливались).
- Навигация по ссылкам (`openExternalUrl`, переходы компонентов через `navigateAndEmit`) и `downloadFile` блокируют опасные схемы URL (`javascript:`, `vbscript:`, `data:` для навигации и т. п.) с предупреждением в консоли. Новые утилиты: `isSafeUrl`, `NAVIGATION_PROTOCOLS`, `DOWNLOAD_PROTOCOLS`.
- `utils` больше не содержит вспомогательные функции Storybook (`storybookUtils`): они импортировали `storybook/test`, которого нет в зависимостях пакета.

**Типы слотов и props**

- Из типов удалены слоты и props, которые компонент объявлял, но не показывал: `default` у 16 компонентов (у BaseIcon, BaseLoader и BaseSkeleton — только в типе `Base<X>Slots`), `event`, `navigation` и проп `events` у `BaseCalendar`, тип `CalendarEvent`. ## Безопасность (порция 1.1)

### BaseEditor очищает HTML

**Что изменилось.** Раньше HTML из `v-model` вставлялся в редактор как есть и так же возвращался в `update:modelValue`. Теперь он очищается встроенной функцией `sanitizeHtml` в пяти местах:
- при показе `v-model`;
- при вставке из буфера обмена;
- при перетаскивании из другой страницы;
- при выходе из режима кода;
- в `update:modelValue`.

Остаются элементы, которые создаёт сам редактор: абзацы, заголовки, списки, цитаты, код, ссылки, изображения, видео, начертания и цвет. Удаляются:
- скрипты и стили;
- `<iframe>`, `<svg>`, формы;
- обработчики `on*`, атрибуты `class`, `id`, `data-*`;
- CSS-свойства вне списка: цвет, фон, выравнивание, начертание, размеры и скругление медиа.

**Что сделать.**
- HTML, который приложение показывает в редакторе, по-прежнему проверяйте на сервере: клиентскую очистку можно обойти, отправив запрос напрямую.
- Если в содержимом нужны классы или другие элементы, передайте свою функцию очистки: `:sanitize="html => DOMPurify.sanitize(html, config)"`.
- Для полностью доверенного HTML очистку можно отключить: `:sanitize="html => html"`.

### Ссылки в BaseEditor

Кнопка «Ссылка» не вставляет адреса с небезопасной схемой (`javascript:`, `data:`, `vbscript:`) и пишет предупреждение в консоль. Адрес без схемы дополняется: `example.com` → `https://example.com`, `team@example.com` → `mailto:team@example.com`.

### Пункты BaseSideBar с небезопасным адресом

Пункт, у которого строковый `to` содержит небезопасную схему, показывается кнопкой без `href` и не передаётся в `linkComponent`; в консоль один раз выводится предупреждение. Клик по такому пункту по-прежнему эмитит `itemClick`.

## Уведомления и окна (порция 1.2)

### BaseApp, useToast, useOverlay, useConfirm

Новое, ничего менять не нужно. Чтобы вызывать уведомления и окна из кода, оберните приложение в `<BaseApp>` и используйте `useToast()`, `useOverlay()`, `useConfirm()` — пример в README, раздел «BaseApp: уведомления и окна из кода». Отдельный `<BaseNotification ref>` для уведомлений приложения больше не нужен.

### BaseNotification

**Что изменилось.**
- Автозакрытие останавливается, пока указатель над уведомлениями или фокус внутри, и продолжается с остатка времени. Раньше уведомление закрывалось, даже если пользователь читал его или стоял на кнопке.
- Уведомление из `add()` без своего `duration` показывается столько, сколько задано пропом `duration` компонента. Раньше — всегда 3 секунды.
- Длительность больше 2³¹−1 мс (почти 25 дней) ограничивается этим значением. Раньше такое значение переполняло таймер, и уведомление закрывалось сразу.
- `add()` возвращает id уведомления. Тип id — `NotificationId` (`string | number`), раньше `number`: так же типизированы `NotificationItem.id` и аргумент `remove()`.
- Новое: `isPersistent` (без автозакрытия), `actions` (кнопки под текстом), управляемый список `items` и событие `remove(id)`, ключ `actions` в `customClass`.

**Что сделать.**
- Если код сохраняет id уведомления в переменную типа `number`, поменяйте тип на `NotificationId`.
- Тесты, которые ждут автозакрытия, не должны держать указатель или фокус над уведомлением.
- Уведомлениям, которые должны закрываться быстрее компонента по умолчанию, передайте `duration` в `add()`.

### BaseModal

Новое, ничего менять не нужно: `dialogRole` (`dialog` или `alertdialog`), `ariaDescribedby`, событие `after-leave` после анимации закрытия.

## Тема, настройки и ссылки (порция 1.3)

### BaseBreadcrumbs: крошки — ссылки

**Что изменилось.** Раньше крошка с `to` была кнопкой и только эмитила `navigate(url)`, а крошка с `href` открывалась через `window.open`. Теперь крошка с адресом — ссылка:
- `to` рендерит компонент ссылок приложения: проп `linkComponent`, `createUiKitPlugin({ linkComponent })` или RouterLink, если подключён vue-router. Без роутера — `<a href>`, и клик переходит по адресу с перезагрузкой страницы;
- `href` — `<a href>`, по умолчанию в новой вкладке, как раньше. Новое поле `target` у крошки меняет это;
- крошка без адреса — кнопка с событием `item-click`, как раньше;
- `navigate(url)` приходит при клике по ссылке, но переход выполняет сама ссылка;
- ссылка «домой» (`showHome`) тоже ссылка, её клик теперь эмитит и `item-click`.

**Что сделать.**

## Слои оверлеев (порция 1.5)

### Escape и клик снаружи — только верхнему слою

**Что изменилось.** Окна, боковые панели, выпадающие списки, меню, подсказки, тур и просмотр изображения стали слоями общего стека (`useLayer`). Раньше каждый компонент слушал `document` сам, и одно нажатие Escape закрывало всё открытое сразу: список и окно, в котором он открыт. Теперь:
- Escape получает только верхний открытый слой с обработчиком Escape. Из окна с открытым списком первое нажатие закрывает список, второе — окно. Если на экране видна подсказка, первое нажатие скрывает её.
- Нажатие, для которого элемент уже вызвал `event.preventDefault()`, и Escape, отменяющий ввод через IME, слои не обрабатывают.
- Нажатие мыши в панели слоя, открытого позже (список в поповере, выбор даты в окне), не считается нажатием снаружи для слоёв под ним.
- Escape у панели эмодзи в чате больше не закрывает окно или боковую панель, в которых открыт чат.

**Что сделать.**
- Если приложение закрывало окно и открытый в нём список одним Escape и тесты это проверяют — ждите два нажатия.
- Свой обработчик Escape внутри окна кита (поле с отменой ввода, свой список) должен вызывать `event.preventDefault()`, иначе то же нажатие закроет и окно.
- Свои всплывающие элементы подключайте через `useEscapeKey` и `useClickOutside` — так они встанут в общий стек.

### useClickOutside и useEscapeKey

**Что изменилось.**
- `useClickOutside` и `useEscapeKey` регистрируют слой: слушатели на `document` общие для всех слоёв и снимаются, когда размонтирован последний. Слой регистрируется при монтировании компонента, как и раньше.
- `useClickOutside` по-прежнему реагирует на `mousedown`; нажатие внутри слоёв, открытых позже, теперь не вызывает `callback`. «Внутри» определяется по пути события (`composedPath`): работает в Shadow DOM и когда обработчик на элементе успел удалить цель нажатия из DOM.

**Что сделать.** Тесты, которые проверяли `document.addEventListener` или `removeEventListener` этих composables, перепишите на поведение: событие `mousedown` или `keydown` и результат.

### useDropdownPosition: переворот и сдвиг у края окна

**Что изменилось.**
- Если на выбранной стороне не хватает места, а на противоположной хватает, панель открывается с противоположной стороны; вдоль края окна она сдвигается, оставляя 8px (`VIEWPORT_MARGIN`). Проп `position` не меняется, фактическая сторона — в новом `placement`.
- `coords` — теперь левый верхний угол панели. Раньше это была точка привязки у триггера, а `panelStyle` выравнивал панель через `right`, `bottom` и `transform`.
- `panelStyle` содержит только `top`, `left`, `maxHeight` и `width` (при `matchWidth`).
- Слушатели прокрутки и изменения окна есть только у открытой панели; размер панели отслеживает `ResizeObserver`.

**Что сделать.**
- Если приложение само вызывало `useDropdownPosition`, не добавляйте к панели `transform` для выравнивания: координаты уже учитывают размер панели.
- Тесты и снимки экрана с панелями у края окна: панель может оказаться с другой стороны триггера.
- В jsdom нужен мок `ResizeObserver` (как и для BaseTable, BaseTabs, BaseSlider).

### Контейнер слоёв и тема панелей

**Новое.**
- `createUiKitPlugin({ teleportTo })` и проп `teleportTo` у `BaseApp` задают, куда телепортируются окна, панели, подсказки и уведомления (по умолчанию `body`). Нужен, например, в полноэкранном режиме.
- Выпадающие панели, подсказки и контекстные меню редактора и чата берут `data-theme` ближайшего предка триггера: панель из тёмного блока на светлой странице — тёмная.
- Composables `useLayer`, `useLayerIndex`, `getOpenLayers`, `useTeleportTarget`, `useInheritedTheme`, ключ `TELEPORT_TARGET_KEY`.

**Что сделать.** Ничего. Если приложение ставило `data-theme` на телепортированные панели через `panelClass` или стили, это можно убрать.

### z-index: порядок открытия и токены

**Что изменилось.** Раньше z-index был задан числами по типу компонента, и при равных значениях порядок наложения решало место якоря Teleport в DOM — момент монтирования компонента, а не открытия. Окно из `App.vue` оказывалось под боковой панелью страницы, а окно, открытое из меню, — под меню (1100 против 1000). Теперь окна, боковые панели, тур, окно поиска, выпадающие панели, календарь и контекстные меню редактора и чата — один стек: z-index = `--rise-z-overlay` + место слоя среди открытых (`--rise-layer-index`). Слой, открытый позже, всегда выше.

| Токен | Значение | Компоненты |
|---|---|---|
| `--rise-z-overlay` | 1000 | основа стека: BaseModal, BaseSlideover, BaseTour, окно BaseSearch, BaseDropdown (и BaseSelect, BasePopover, BaseSearch), панель BaseDatePicker, меню BaseEditor и BaseChat; подменю BaseMegaMenu (без места в стеке, как раньше — 1000) |
| `--rise-z-toast` | 2000 | BaseNotification |
| `--rise-z-tooltip` | 3000 | BaseTooltip |
| `--rise-z-max` | 9999 | просмотр изображения BaseImage |

Что сдвинулось:
- выпадающие панели, календарь и контекстные меню — 1000 + место вместо 1100: над окном, только если открыты позже него (список в окне — как раньше, над окном);
- подсказка — 3000 вместо 9999: теперь под просмотром изображения.

**Что сделать.**
- Если у приложения свои слои между этими значениями (липкая шапка, чат поддержки), переопределите токены в `:root`, а не z-index в стилях компонентов.
- Свой телепортированный элемент, который должен вставать в общий порядок, — `useLayerIndex` и `z-index: calc(var(--rise-z-overlay) + var(--rise-layer-index, 0))`.

- Новый проп `name`: ошибку проверки `BaseForm` по схеме обёртка показывает сама.
- Звёздочка обязательного поля (у обёртки и у подписей BaseInput, BaseTextarea, BaseSelect, BaseRadio, BaseSwitch) скрыта от скринридера (`aria-hidden`): имя поля больше не заканчивается на «*».

**Что сделать.**
- Уберите `for` у обёртки вокруг контрола кита — он больше не нужен (с `for` подпись связывается с указанным id, как раньше).
- Тесты, которые искали поле по имени со звёздочкой (`getByLabelText('Email *')`), — на имя без неё. Тесты, которые сразу после `mount` проверяли связь подписи обёртки с полем, — после `await nextTick()`.

### BaseForm: проверка по схеме и блокировка кастомных контролов

**Что изменилось.**
- `schema` — схема Standard Schema (Zod 3.24+, Valibot 1.0+, ArkType 2.0+), `state` — данные формы. Со схемой отправка сначала проверяет `state`: при ошибках приходит `invalid` (список `{ name, message }`), ошибки показывают BaseFormField с тем же `name`, фокус уходит на первое поле с ошибкой, `submit` не приходит. После первой отправки проверка повторяется при каждом изменении `state`. `submit` приходит после проверки — асинхронно.
- `submit` получает вторым аргументом данные: после схемы или `state` без неё.
- Через ref: `validate()` (промис с `{ value, issues }`), `reset()` и `errors`.
- Отключённая или отправляемая форма блокирует кастомные контролы кита: BaseSelect, BaseRange, BaseRating, BaseFileUpload, BaseCheckboxGroup (отключены) и BaseEditor (только чтение). Раньше их нужно было блокировать собственными props.

**Что сделать.** Уберите ручную блокировку этих контролов по `isLoading` формы. Обработчик `submit` со схемой вызывается не синхронно с событием отправки — не рассчитывайте на это в тестах (ждите `waitFor`).

## Эпик chat: BaseChat — значки участников и закрепы (порция Р.5)

**Что изменилось.**
- Закреплённые сообщения: панель показывает последнее закреплённое, а не первое; новый закреп сразу становится показанным. Клик по панели прокручивает ленту к сообщению и переключает панель на предыдущее закреплённое, по кругу; стрелки листают вручную, тоже по кругу.

**Что сделать.** Если тесты приложения ищут рейтинг по тексту «N.5 из 5» или «Оценка 4.5 из 5», замените точку на запятую. Для выбора десятых включите `step: 0.1` и `isValueShown`.

## Задача fu-range: клавиатура и проверка значений Range, Rating, Separator, Skeleton

**Что изменилось.**

- **BaseRange, клавиатура (APG Slider).** У ползунка добавились клавиши: Home — к `min` (у диапазона и точек — к соседнему ползунку), End — к `max` (или к соседу), PageUp и PageDown — на 10 шагов `step`. Как и стрелки, каждая клавиша эмитит `update:*` и `change`; упор в границу `change` не даёт. Раньше эти клавиши не обрабатывались и, например, прокручивали страницу — теперь `preventDefault`.
- **BaseRange, проверка пропсов.** `min` и `max` не числа (NaN, Infinity) — берутся 0 и 100; `max < min` — диапазон сводится к `min` (как у нативного `<input type="range">`); `step` ≤ 0 или не число — шаг 1. Значение (`modelValue`, `rangeValue`, `points`) вне границ показывается на ближайшей границе: ползунок, заливка, подпись и `aria-valuenow` больше не выходят за `aria-valuemax`. Значение не число — показывается `min`. v-model при этом не переписывается: новое значение придёт только после действия пользователя.
- **BaseRating.** `step` ≤ 0 или не число — шаг 1 (раньше клик и стрелки давали NaN). Дробный `max` округляется до ближайшего целого (4.6 → 5 звёзд), `max` ≤ 0 — 5. Оценка больше `max` показывается как `max` (`aria-valuenow`, `aria-valuetext`, заливка, SEO-разметка), меньше 0 — как 0, не число — 0.
- **BaseSeparator.** `thickness` 0, меньше 0 или NaN — линия 1px (раньше линия пропадала). `spacing` без подписи теперь даёт отступ поперёк линии: сверху и снизу у горизонтальной, слева и справа у вертикальной (раньше без подписи не действовал). С подписью — как раньше. Отрицательный и NaN `spacing` не применяются.
- **BaseSkeleton.** `width`/`height` = 0 — `0px` (раньше проп отбрасывался). Ключевые слова CSS (`'auto'`, `'fit-content'`, `'max-content'`) при `sizeScale` ≠ 100 не оборачиваются в `calc` (раньше давали невалидный `calc(auto * 1.5)` и размер пропадал). Отрицательное число и NaN не применяются. `shape="circle"` без высоты — круг по ширине (`aspect-ratio: 1`).
- **`useRangeValues`.** В возврате (`UseRangeValuesReturn`) новое поле `bounds: ComputedRef<RangeBounds>` — проверенные границы `{ min, max, step }`, по которым считаются значения и ARIA. Тип `RangeBounds` экспортируется из `@ramzes1385/rise-ui-kit/composables` (с задачи small-fixes-7a). Изменение добавочное; моки и свои объекты типа `UseRangeValuesReturn` нужно дополнить полем `bounds`.
- **Предупреждения.** О каждом заменённом или неприменённом значении — `console.warn` с префиксом `[rise-ui-kit]`: имя компонента, пропа, что пришло и что используется. Строки — новый раздел словаря `valueWarnings` (`UI_VALUE_WARNINGS`); свой язык через `defineLocale` его переводит. Значение вне границ у Range и Rating предупреждения не даёт: так бывает и в рабочем приложении, когда `max` меняется раньше значения.

**Что сделать.** Обычно — ничего. Если в консоли появилось предупреждение `[rise-ui-kit] BaseX: …` — исправьте проп, который оно называет. Приложение, которое само перехватывало Home/End/PageUp/PageDown на ползунке BaseRange, теперь получит их обработку китом. Отступ у `BaseSeparator :spacing` без подписи — если он не нужен, уберите `spacing`.

Смена шага объявляется в скрытом `role="status"`: «Шаг 2 из 3: Импорт» (словарь `tour.STEP_STATUS`, `tour.STEP_STATUS_TITLED`). Тесты, искавшие окно по `aria-label`, ищите по роли и имени: `getByRole('dialog', { name: 'Импорт' })`.

**useFocusTrap.** Новая необязательная опция `getLinkedElements` — элементы вне контейнера, до которых доходит Tab. Без неё поведение прежнее.

**BaseTabs — значок вкладки через BaseIcon (TAB-3), несовместимо.** `TabItem.icon` — теперь имя иконки BaseIcon (`'settings'`), а не HTML-строка: строка больше не вставляется через `v-html`, вставка разметки из данных невозможна. Своя разметка значка — слот `icon` (`{ item }`):

```vue
<!-- было -->
<BaseTabs :items="[{ id: 'a', label: 'Профиль', icon: '<svg>…</svg>' }]" v-model="tab" />
<!-- стало -->
<BaseTabs :items="[{ id: 'a', label: 'Профиль', icon: 'home' }]" v-model="tab" />
<BaseTabs :items="items" v-model="tab">
	<template #icon="{ item }"><MySvg :name="item.id" /></template>
</BaseTabs>
```

Значок декоративный (`aria-hidden`): имя вкладки — только `label`.

**BaseTabs — события (TAB-6, TAB-8).** Клик по уже выбранной вкладке больше не эмитит `change` и `update:modelValue`. После перетаскивания списка вкладок мышью следующий клик или Enter по вкладке больше не теряется; перетаскивание начинается только основной кнопкой мыши.

## fu-table-tree — BaseTree

**Что изменилось.** Выбор `multiple`, клавиатура слота `actions`, асинхронные `items` и защита от плохих данных (аудит TRE-4, TRE-5, TRE-7, TRE-8, TRE-9, TRE-11).

- **Каскад в `multiple` (TRE-4).** Выбор считается снизу вверх. Узел отмечает своих доступных потомков. Когда отмечены все доступные дети, отмечается и родитель: его id попадает в `selectedIds`. Если отмечена часть детей, у родителя частичный выбор: флажок с чертой (`isIndeterminate` у BaseCheckbox), у `treeitem` атрибут `aria-checked="mixed"`, в `selectedIds` родителя нет. Снятие отметки с одного ребёнка снимает её со всех предков. Раньше родитель оставался в `selectedIds`.
  - Отключённый узел (`isDisabled`) и его поддерево в каскад не входят и в подсчёт не попадают. Их состояние в `selectedIds` остаётся таким, каким его передали. `selectNode` для отключённого узла ничего не делает в любом режиме, и `select` не приходит.
  - Пробел или клик по узлу с частичным выбором отмечает всё доступное поддерево.
  - Если переданный `selectedIds` противоречив (например, `['folder']` без детей), дерево показывает его согласованным: дети `folder` тоже отмечены. Событие при монтировании не отправляется. Первое же переключение отправит в `update:selectedIds` согласованный список. Порядок id сохраняется, новые id добавляются в конец. Ребёнок, добавленный в папку из `selectedIds`, тоже показывается отмеченным.
  - Пример: `selectedIds: ['use-auth']` в папке `composables` (`use-auth`, `use-api`). Папка показывается частично выбранной. Пробел на `use-api` отправит `['use-auth', 'use-api', 'composables']`, а если отмечены уже все узлы `src` — ещё и `src`.
- **Смена `selectionMode` (TRE-11).** При переходе в `single` остаётся первый id из `selectedIds`. Если id было больше одного, уходит событие `update:selectedIds` с массивом из одного id. До ответа родителя в режиме `single` показывается только первый id. При переходе в `none` `selectedIds` не меняются и событие не отправляется. Подсветка `base-tree__node--selected` по `selectedIds` в режиме `none` остаётся как раньше.
- **Слот `actions` (TRE-7).** Клик внутри обёртки `.base-tree__actions` не всплывает до узла: кнопка не выбирает и не раскрывает его, в том числе с Enter и пробелом. `@click.stop` на своих кнопках больше не нужен. В порядке Tab — только действия узла, который сам в порядке Tab (roving tabindex по APG). У фокусируемых элементов слота в остальных узлах ставится `tabindex="-1"`, а прежнее значение хранится в `data-rise-tree-tabindex`. Когда узел становится текущим, значение возвращается. Tab с текущего узла ведёт в его действия, следующий Tab — из дерева. Фокус на кнопке действий (мышью или программно) делает её узел текущим. Сигнатура слота не изменилась (`{ node }`). Событие `keydown` внутри действий не останавливается: Escape и сочетания приложения работают.
- **`isDefaultExpandAll` и `items`, пришедшие позже (TRE-5).** Узлы с детьми, которых дерево ещё не видело, раскрываются при каждой смене `items`. Например, сначала `[]`, потом данные с сервера. Узел, который пользователь свернул, при новых `items` с тем же id остаётся свёрнутым. При включении флага раскрываются все узлы. Раскрытые id добавляются к текущим `expandedIds`, а не заменяют их.
- **`items: undefined` (TRE-8).** Дерево рисуется пустым без ошибки. Vue по-прежнему предупреждает о типе пропа.
- **Циклы и повторные id (TRE-9).** Обходы дерева идут без рекурсии и с учётом пройденных id: цикл в `children` больше не даёт бесконечную рекурсию и `RangeError` при монтировании, раскрытии или `isDefaultExpandAll`. Повторное вхождение id не показывается — на любом уровне, включая корень и соседей одного родителя: показывается первое вхождение в порядке обхода. Это и цикл, и дубль id под другим родителем. Клавиатура (→, ←, `*`) видит тех же детей, что и экран. В консоль выводится предупреждение `[rise-ui-kit] BaseTree: id узлов встречаются в дереве повторно …` (ключ `warnings.TREE_REPEATED_ID`). Раньше дубли показывались, но делили раскрытие и выбор. Если `items` реактивны (`reactive`/`ref` с глубокой реактивностью), индекс дерева пересчитывается и после правки `children` на месте.
- **`useTreeState` и `treeUtils`.** `items` принимает `Ref<TreeNode[] | undefined>`. Результат дополнен `indeterminateSet` (частичный выбор), `roots` (корень без повторов) и `childrenOf(node)` (дети без повторов; без повторов — тот же массив `children`). Предупреждение о повторах выводится один раз на набор повторных id, а не при каждой правке `items`. `selectedIds` в режиме `multiple` возвращается согласованным, в `single` — не длиннее одного id. Внутренний кэш потомков убран. В `utils` появились `buildTreeIndex`, `getTreeChildren`, `getTreeRoots`, `normalizeTreeSelection`, `toggleTreeSelection` и типы `TreeIndex`, `TreeSelectionState`. `collectDescendantIdsInto`, `buildDescendantsCache` и `collectExpandableIds` с прежними сигнатурами теперь работают без рекурсии и пропускают повторные id. `buildDescendantsCache` не кладёт узел в его собственный список.

**Что сделать.**
- Если приложение в режиме `multiple` само дописывало родителя в `selectedIds` или убирало его, уберите этот код: состояние родителя считает дерево. Если приложение ждало, что родитель останется отмеченным после снятия ребёнка, учтите новое правило.
- Тесты, которые сравнивают `update:selectedIds` после снятия отметки с ребёнка, ждут список без предков.
- `@click.stop` на кнопках слота `actions` можно убрать. Если тесты переходили по кнопкам действий через Tab, теперь эти кнопки достижимы только у текущего узла.
- Проверьте `items` на уникальность id во всём дереве: повторы больше не показываются.

## fu-table-tree — BaseTable

**Что изменилось.** Страница, выбор и догрузка при смене `rows`, «Выбрать все» в частичном состоянии, клавиатура строк и ресайза, закреплённые колонки, слоты заголовка и пустой таблицы, поиск (FOLLOW_UPS № 7, № 31; аудит TBL-2, TBL-3, TBL-4, TBL-8, TBL-9, TBL-10, TBL-12, TBL-14, TBL-16, TBL-17, TBL-19).

- **Смена `rows` (TBL-3).** Новая ссылка `rows` (рефетч, поллинг, `map`) больше не возвращает на первую страницу: страница остаётся, пока она есть, а если строк стало меньше — сдвигается на последнюю существующую (и при `splice`). Выбор, сделанный пользователем, сохраняется у строк, которые остались; строки, которых больше нет, выпадают из выбора, и тогда приходит `select` с оставшимися строками. `isSelected` строки применяется, если строка новая или родитель изменил значение флага; неизменённый флаг выбор пользователя не перетирает.
- **Догрузка (TBL-4).** В режимах `button` и `infinite` строки, которые родитель дописал в `rows`, больше не «схлопывают» таблицу до `pageSize`: показанные строки остаются, следующая порция — по `load-more`. Число показанных строк сбрасывается поиском, фильтром и сменой размера страницы.
- **Новый проп `hasMore` (TBL-4).** Серверная подгрузка: при `hasMore: true` кнопка «Загрузить еще» и подгрузка прокруткой работают, даже когда все переданные строки уже показаны. Родитель по `load-more` дописывает строки и снимает флаг, когда данных больше нет.
  ```vue
  <BaseTable :rows="rows" :columns="columns" load-mode="button" :page-size="20" :has-more="hasMore" @load-more="loadNext" />
  ```
- **Смена `pageSize` (TBL-8).** Новый `pageSize` из пропса возвращает на первую страницу и сбрасывает догрузку; раньше оставалась прежняя страница с пустым телом.
- **Поиск (TBL-9, TBL-10).** Страница сбрасывается сразу при вводе, а не после `searchDebounce` (раньше на 300 мс показывалось «Нет данных»). Поиск идёт только по видимым колонкам — по значению и по тексту `formatter`; поля вне `columns`, скрытые колонки и пустые значения (`null`, `undefined`) больше не находятся; пробелы по краям запроса не учитываются, «ё» и «е» не различаются.
- **«Выбрать все» (№ 7, TBL-2).** Когда выбрана часть доступных строк найденного набора, флажок в шапке в частичном состоянии (`isIndeterminate` у BaseCheckbox, `indeterminate` у поля). Если доступных строк нет (все отключены или скрыты поиском), флажок неактивен.
- **Пустая таблица.** Строки есть, но поиск или фильтры скрыли все — текст «Ничего не найдено» (новый проп `emptyFilteredText`, словарь `table.EMPTY_FILTERED`). Слот `empty` получает `{ isFiltered }`. `emptyText` («Нет данных») — только когда строк нет.
  ```vue
  <template #empty="{ isFiltered }">{{ isFiltered ? 'Измените запрос' : 'Заказов пока нет' }}</template>
  ```
- **Строки с клавиатуры.** Если у таблицы есть слушатель `row-click`, строки становятся одной точкой Tab (roving tabindex): ↑/↓, Home и End переводят фокус между строками, Enter и пробел дают `row-click`. У строк атрибут `data-row-interactive`, курсор `pointer` и кольцо фокуса. Без слушателя строки, как раньше, не фокусируются.
- **Клик по элементам в ячейке (TBL-17).** Клик по кнопке, ссылке, полю или `[role=button]` внутри ячейки больше не даёт `row-click` и не раскрывает строку. Клик по отключённой строке (`isDisabled`) даёт `row-click`, но не раскрывает её.
- **Ресайз с клавиатуры (TBL-12).** Ручка ресайза — `role="separator"` с `tabindex="0"`, именем «Ширина колонки: <заголовок>», `aria-valuenow` (ширина ячейки в px), `aria-valuemin` (50), `aria-valuemax` (ширина плюс то, что можно забрать у соседа до его минимума) и `aria-valuetext` («120px»); ← и → меняют ширину на 10px, с Shift — на 50px, от ширины ячейки на экране, как перетаскивание (колонка с `width: '20%'` или растянутая раскладкой не сжимается рывком); события те же: `column-resize` и `columns-change`. Перетаскивание начинается только левой кнопкой мыши.
- **Закреплённые колонки (TBL-19).** Если есть колонки `isSticky: 'left'`, служебные колонки (выбор, номер, раскрытие) тоже закрепляются, а закреплённые колонки встают за ними с накопленным смещением: несколько колонок слева и справа больше не налезают друг на друга и на чекбоксы. Смещения считаются по ширинам ячеек шапки (ResizeObserver) и пишутся в `style.left`/`style.right` ячеек; у таблицы класс `base-table__table--sticky-service` и переменные `--tbl-sticky-check`, `--tbl-sticky-number`, `--tbl-sticky-expand`.
- **Слот `header-<key>`.** У сортируемой колонки слот рисуется внутри кнопки сортировки: значок направления, приоритет и `aria-sort` остаются, сортировка доступна с клавиатуры. Раньше слот заменял кнопку целиком. Новый проп слота `sortDirection` (`'asc' | 'desc' | null`). В слоте сортируемой колонки не должно быть своих кнопок и ссылок.
- **События `sort` и `filter` (TBL-16).** Получают копии состояния: сохранённый payload больше не меняется при следующей сортировке или фильтре.

**Что сделать.**
- Если приложение само возвращало пользователя на страницу после рефетча или восстанавливало выбор после новой ссылки `rows` — этот код можно убрать.
- Если приложение ждало сброса страницы или выбора после смены данных — управлять страницей и выбором снаружи BaseTable пока нельзя (нет пропа страницы, `defineExpose` и сброса выбора; FOLLOW_UPS № 62). Обходы:
  - **снять выбор после действия** (удалили выбранные, рефетч) — держите выбор в `isSelected` строк: по событию `select` отмечайте выбранные строки `isSelected: true`, а в новых `rows` после действия передайте `isSelected: false`. Изменённый родителем флаг применяется и снимает выбор:
    ```ts
    const selectedIds = ref(new Set<string | number>())
    const onSelect = (selected: TableRow[]) => (selectedIds.value = new Set(selected.map((row) => row.id)))
    const tableRows = computed(() => rows.value.map((row) => ({ ...row, isSelected: selectedIds.value.has(row.id) })))
    async function removeSelected() {
    	await api.remove([...selectedIds.value])
    	selectedIds.value = new Set() // флаг у оставшихся строк станет false — выбор снимется
    	rows.value = await api.list()
    }
    ```
  - **вернуться на первую страницу и сбросить всё состояние** (новый отчёт, другой набор данных) — смените `key` у BaseTable: таблица пересоздастся с первой страницы, без выбора, сортировки и поиска.
    ```vue
    <BaseTable :key="reportId" :rows="rows" :columns="columns" />
    ```
  - Смена `pageSize` из пропса по-прежнему возвращает на первую страницу (TBL-8).
- Серверная подгрузка: передавайте `hasMore` и дописывайте строки в `rows` по `load-more`.
- Тесты, которые ждали сброса страницы через `searchDebounce`, или поиска по полям вне колонок, — обновить.
- Слоты `header-<key>` сортируемых колонок: уберите из них свои кнопки сортировки; подпись слота окажется внутри кнопки.
- Если обработчик `row-click` полагался на клики по кнопкам внутри ячеек — повесьте обработчик на саму кнопку.

## small-fixes-7d — BaseChart и BaseCountdown

- `BaseChart`: Escape на области графика вызывает `preventDefault()` только когда выбрана точка (снимает подсказку). Без выбранной точки Escape уходит дальше — модалка или выпадающее окно вокруг графика закрываются.
- `BaseChart`: строка `charts.CHART_HINT` (ru, en) называет все клавиши: стрелки, Home/End, PageUp/PageDown, Escape. Приложения, переопределившие строку, могут её дополнить.
- `BaseCountdown`: строка `to` только с датой (`2026-10-05`) теперь читается как местная полночь, а не полночь UTC (как у `Date.parse`). Строка с временем без смещения (`2026-10-05T12:00`) — по-прежнему местное время; со смещением или `Z` — точный момент. Время с сервера передавайте со смещением.
- `BaseCountdown`: слот `finished` больше не под `aria-hidden` — скринридер читает его вместо «время вышло», ссылки и кнопки в нём доступны; скрытый текст `.base-countdown__spoken` при показе слота не выводится. Слот default по-прежнему только для вида (под `aria-hidden`): интерактивное — рядом с компонентом или в `finished`.
- `BaseCountdown`: при рендере на сервере и гидратации первая отрисовка — заглушка `--` (части времени — нули, `isFinished: false`), настоящее время — после монтирования. HTML сервера не зависит от его часов, гидратация без расхождений. В обычном приложении (без SSR) первая отрисовка сразу с настоящим временем.

## Задача small-fixes-7b: поля со своей подписью в BaseFormField, клавиатура BaseAccordion

Несовместимое (коммит `fix(form)!`):

- **BaseCheckbox и BaseSwitch со своей подписью, BaseRadio со своим заголовком внутри BaseFormField с подписью (`label`)** больше не получают `aria-invalid` и `aria-describedby` обёртки. Обёртка в этом случае — группа (`role="group"`) с подписью, описанием и ошибкой обёртки: скринридер читает ошибку при входе в группу, а не повторяет её у каждого флажка. Собственные `error`, описание и `inputAttrs['aria-describedby']` контрола остаются; `aria-required` и цвет ошибки обёртки — тоже.
  - Было: `<BaseFormField label="Условия" error="Примите условия"><BaseCheckbox label="Принимаю" /></BaseFormField>` — у флажка `aria-invalid="true"` и описание «Примите условия».
  - Стало: описание «Примите условия» у группы «Условия», у флажка — нет. Нужна ошибка именно на флажке — передайте её флажку (`error`), а не обёртке.
  - Обёртка группой не стала (нет `label`, задан `for` или в ней уже есть поле без своей подписи) — как раньше: `aria-invalid` и описание обёртки у контрола. `<BaseFormField error="Примите условия"><BaseCheckbox label="Принимаю" /></BaseFormField>` — у флажка `aria-invalid="true"` и описание «Примите условия».
- **`FormFieldContext`** — новое необязательное поле `isGroup` (обёртка — группа). Свой провайдер `FORM_FIELD_CONTEXT_KEY` без него работает как раньше: группой считается обёртка с подписью (`hasLabel`).
- **BaseRadio с `label` внутри BaseFormField с `label`**: раньше подпись обёртки ни к чему не была привязана; теперь обёртка — группа со своей подписью, внутри — `radiogroup` со своей.
- **`useFieldControl`**: `hasOwnLabel` принимает значение, ref или геттер (`MaybeRefOrGetter<boolean | undefined>`) и реактивен — подпись, появившаяся позже, освобождает обёртку, пропавшая — подключает контрол к подписи обёртки. `isInField` в ответе — геттер: читайте его из объекта (`control.isInField`), а не деструктуризацией. BaseCheckbox и BaseSwitch передают подпись реактивно (у BaseSwitch — и слот `label`, и описание из слота `default`, появившиеся после монтирования).
- **BaseTree и BaseChat** вызывают `isolateFormField()`: внутри BaseFormField флажки узлов и выбора сообщений не берут подпись, ошибку и обязательность обёртки (как BaseTable и BaseCalendar).

Новое:

- **BaseAccordion**: стрелки ↓/↑ переводят фокус на следующий и предыдущий заголовок (по кругу), Home и End — на первый и последний (необязательные клавиши APG Accordion). Пункты не раскрываются, Tab, Enter и Space — как раньше; с Ctrl, Alt и Meta клавиши не перехватываются. Вложенный аккордеон в панели — свой порядок.

Что сделать: тесты приложения, которые ждали `aria-invalid` у флажка, переключателя или группы радиокнопок со своей подписью внутри BaseFormField с подписью и ошибкой, — проверять описание группы обёртки (`getByRole('group', { name })` + `toHaveAccessibleDescription`).

## Задача new-cryptopro-ui: BaseCryptoProSign

Новый компонент, изменений в существующих нет.

- `BaseCryptoProSign` — подпись и проверка подписи через КриптоПро ЭЦП Browser plug-in на `useCryptoPro`: диагностика, выбор сертификата, присоединённая и отсоединённая подпись, хэш больших файлов (`hashThreshold`), уровни `bes`, `t`, `xlt1` со службой штампов `tsaAddress`, `mode="verify"`. Справочник — docs/reference/COMPONENTS.md, «BaseCryptoProSign».
- Экспорт: `BaseCryptoProSign`, `CRYPTO_PRO_SIGN_LEVELS`, `CRYPTO_PRO_SIGN_MODES`, `CRYPTO_PRO_SIGN_VARIANTS`, типы `CryptoProSignResult`, `CryptoProVerifyResult`, `CryptoProVerifySigner`, `CryptoProSignLevel`, `CryptoProSignMode`, `CryptoProSignSource`, `BaseCryptoProSignExpose`. Эмуляция плагина (`createCryptoProSignEmulation`) — внутренняя, в пакет не экспортируется; подпись в приложении проверяйте с настоящим плагином.
- Словарь: в раздел `cryptopro` (ru, en) добавлены тексты компонента; в `plural` — `CRYPTOPRO_EXPIRES`; в `warnings` — `CRYPTOPRO_NO_TSA`. Свой язык — `defineLocale(en, { cryptopro: { … } })`.
- `scriptUrl` можно задать один раз: `createUiKitPlugin({ defaults: { BaseCryptoProSign: { scriptUrl } } })`.
- Исправление по проверке 02.10: в `mode="verify"` строка `data` описывается «Проверяем подпись текста, N Б» (ключ словаря `cryptopro.SOURCE_TEXT_VERIFY`, ru и en); при `color.text` подписи вложенных BaseSelect, BaseSegmented и BaseFileUpload берут этот цвет.
